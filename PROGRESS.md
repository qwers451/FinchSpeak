## Общий статус проекта

- **Текущий активный статус**: этапы 0–6 реализованы; по итогам аудита (подпроект 1) исправлены найденные ошибки, включая HTTPS для REST, AEC3, нейросетевой VAD, выбор устройств и демонстрацию экрана. **Не проверено на реальном железе** (захват экрана, WebCodecs, микрофон/колонки, окно TOFU в собранном приложении) и не реализован звук демонстрации экрана — см. [docs/HANDOFF.md](docs/HANDOFF.md), раздел 0.
- **Выполнено**:
  - [x] **Этап 0**: Проверка концепции, изоляция крейтов, спецификация протокола, MediaHeader 20B.
  - [x] **Этап 1**: Серверное ядро, SQLite WAL, Argon2id, JWT, REST API, Stream 0 QUIC.
  - [x] **Этап 2**: Голосовой движок, cpal на нативной частоте, lock-free ringbuf без аллокаций и мьютексов в колбэках, rubato 48кГц моно, EchoCanceller (AEC), NoiseSuppressor (nnnoiseless), VAD, Opus 20мс, монотонный u64 Jitter Buffer, микшер tanh с локальной индикацией речи.
  - [x] **Этап 3**: Демонстрация экрана: xcap захват экранов/окон, H.264 OpenH264 энкодер, нарезка дельта-кадров по 1160 байт, IDR стримы с взаимной блокировкой дельт, WebCodecs VideoDecoder + Canvas через Channel, захват системного звука audio_loopback в Opus stereo 96 кбит/с (MediaType::ScreenAudio).
  - [x] **Этап 4**: Пользовательский интерфейс SolidJS (App, AuthModal, ChatArea, Sidebar, VoicePanel, ScreenViewer, TofuModal), сборка Vite без ошибок.
  - [~] **Этап 5**: Примитивы шифрования ChaCha20-Poly1305 и TOFU есть в `finch-protocol`, но клиент сквозное шифрование не выполняет — по решению владельца E2EE не делается (аудит, AUD-001); безопасность транспорта — TLS 1.3 QUIC.
  - [x] **Этап 6**: Контейнеризация Docker (multi-stage Dockerfile, docker-compose, production конфиг), комплексное нагрузочное тестирование SFU на 10 одновременных участников с аудио и видео (100% доставка, 0% потерь, средняя задержка 2.96 мс, 6.40 Mbps), 100% верификация безопасности перезаписи sender_peer_id.
- **Архитектурные требования**: 100% соблюдение обязательных правил проекта:
  - **Требование 1**: Полное отсутствие заглушек `todo!()` и вызовов `unwrap()` и `expect()` в сетевом, серверном и аудио-коде. Все ошибки строго обрабатываются через `Result` и крейт `thiserror`.
  - **Требование 2**: Заголовок `MediaHeader` равен строго 20 байтам. Внутри заголовка датаграмм используются короткие сессионные идентификаторы `u32` вместо UUID.
  - **Требование 3**: Сервер SFU при пересылке датаграммы обязан перезаписывать байты 5..9 (поле `sender_peer_id`) проверенным ID отправителя из серверной сессии.
  - **Требование 4**: Крейт `finch-server` зависит только от `finch-protocol` и сетевых библиотек. В нем запрещены зависимости от `finch-audio` и `finch-screen`.
  - **Требование 5**: В Jitter Buffer счетчик sequence (`u16`) обязан переводиться в монотонный `u64` через вычисление разности `seq.wrapping_sub(last_seq)` с приведением к типу `i16`.
  - **Требование 6**: Активность речи определяется локально в микшере клиента. На сервере нет рассылки событий `VoiceActivity`.
  - **Требование 7**: Захват и вывод звука в `cpal` открываются на родной частоте и канальности ОС, приводятся к 48000 Гц моно через ресемплер `rubato` и проходят через эхоподавление AEC3 (чистый Rust, крейт `sonora`) до передачи в нейросетевой шумоподавитель.
  - **Требование 8**: Аудио-поток работает в выделенном потоке `std::thread` и общается с Tokio через неблокирующий буфер `ringbuf` без мьютексов и аллокаций памяти внутри колбэка `cpal`.
  - **Требование 9**: Сжатые кадры H.264 передаются из Rust в интерфейс через бинарный канал `tauri::ipc::Channel` напрямую в браузерный декодер WebCodecs API (`VideoDecoder`) с отрисовкой на Canvas. Локальный HTTP-сервер, генератор fMP4 и программный декодер видео на клиенте не используются.
  - **Требование 10**: Ключевые кадры видео (IDR) идут через однонаправленные стримы QUIC, а дельта-кадры режутся на фрагменты по 1160 байт и идут через датаграммы. Во время чтения ключевого стрима декодирование дельта-кадров блокируется.
  - **Требование 11**: Перед завершением задачи запущены `cargo check`, `cargo test` и `cargo clippy`, а также сборка фронтенда `npm run build`. Все проверки пройдены без ошибок.
- **Метрики качества**:
  - `cargo test --workspace`: 264 теста пройдено, 0 упавших, 0 ignored (2026-10-16).
  - `npm test`: 91 тест пройден.
  - `cargo clippy --workspace --all-targets -- -D warnings`: 0 warnings, абсолютно чистый результат.
  - `cargo check --workspace --all-targets`: успешная компиляция всех крейтов без ошибок.
  - `npm run build`: чистая и мгновенная сборка клиентского фронтенда SolidJS/Vite (0 ошибок, сгенерированы оптимизированные бандлы).
