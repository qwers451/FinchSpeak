# FinchSpeak 1.2.3 — диагностическая сборка

Отдельная тестовая сборка для поиска прерывистого/роботизированного локального звука на Windows. Не является новым стабильным выпуском и не предлагается всем клиентам автообновлением. Сервер 1.2.1 совместим, обновлять его не нужно.

## Как получить отчёт на проблемном ПК

1. Установите эту сборку, войдите в пустую голосовую комнату и откройте настройки «Голос и звук».
2. Выберите нужные микрофон и выход явно. Выключите «Слышать себя».
3. В разделе диагностики нажмите «Начать / сбросить», затем несколько раз выполните «Проверить микрофон» с обычной речью.
4. После окончания теста включите «Слышать себя» на 15–20 секунд, произнесите несколько фраз и выключите его. Не запускайте оба режима одновременно.
5. Нажмите «Остановить», затем «Сохранить отчёт». Передайте файл `finchspeak-audio-diagnostics.json` в этот чат и укажите, в каком режиме слышались прерывания.

Для сравнения можно повторить тот же порядок на ПК с хорошим звуком. Новое нажатие «Начать / сбросить» очищает предыдущий сеанс; сначала сохраните нужный отчёт.

## Что собирается

Названия устройств, их частоты, каналы и форматы, размеры и интервалы callback, потери отсчётов захвата, недостающие отсчёты вывода, задержки обработки и пополнения очереди, потери мониторинга и отбрасывание кадров теста активацией до восстановления preroll. Отдельно указан закрытый push-to-talk. Счётчики приблизительны во время работы и накопительны между переключениями устройств; поколения аудиопотоков отмечены явно. История ограничена 120 снимками примерно раз в секунду. 95-й перцентиль времени DSP — верхняя граница корзины гистограммы, а не точное измерение.

Голос, PCM, пакеты, сообщения, пароли и токены не записываются. Отчёт сохраняется только по нажатию кнопки и автоматически никуда не отправляется. Набор счётчиков сам по себе не доказывает артефакты RNNoise/AEC при отсутствии пропусков.

Сборка также содержит адаптацию очереди воспроизведения к фактическому размеру запроса устройства. Это исправляет воспроизведённое истощение очереди при крупных callback, но причина на конкретном ноутбуке пока не подтверждена. Исправления остальных найденных edge cases в этот диагностический этап не включены, чтобы отчёт помог установить источник проблемы.
