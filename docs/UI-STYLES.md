# Стили интерфейса

Как устроены стили FinchSpeak и куда вносить правку, чтобы она не потерялась в каскаде. Все файлы лежат в `app/frontend/src/styles/`.

В приложении две темы: **Claude Dark** (по умолчанию) и **Finch Custom**. Тема выбирается в «Профиль и настройки → Внешний вид» и записывается в атрибут `data-theme` на `<html>` (`claude` или `custom`). Размер текста (Маленький / Средний / Большой) работает через масштаб `--zoom` на `.shell`, а не через размеры шрифтов: правило с `px` не нужно умножать на коэффициент.

## Порядок файлов

Файлы подключаются в `src/index.tsx` в таком порядке; при равной специфичности побеждает тот, что ниже.

| № | Файл | Что в нём |
| --- | --- | --- |
| 1 | `finch.css` | Базовая дизайн-система: переменные, кнопки, поля, метки, строки каналов, сообщения, разделители дней. Размеры «по макету». |
| 2 | `app.css` | Правила приложения поверх базы: раскладка, поведение элементов (прокрутка, всплывающие окна, действия канала). |
| 3 | `custom-tokens.css` | Сырые значения темы Finch Custom: палитра, шрифты, срез углов. Селекторов компонентов здесь нет. |
| 4 | `themes.css` | Обе темы: смысловые переменные (`:root, [data-theme="claude"]` и `[data-theme="custom"]`), размеры и отступы по темам, окна ≤1150, ≤940 и ≤720 px. |
| 5 | `motion.css` | Анимации и переходы. |
| 6 | `polish.css` | Правки «по содержимому»: минимумы, прокрутка, перенос, ограничение ширины — то, что нужно в самых узких окнах и при большом тексте. |

Важно:

- Селектор `[data-theme="custom"] .x` имеет специфичность выше, чем `.x`: он побеждает независимо от порядка файлов. Поэтому правило для одной темы всегда пишется с префиксом.
- `!important` в новых правилах не добавляем. В старых правилах `themes.css` они есть (около 15 строк на все файлы) — их не трогаем без отдельной причины.
- Не переписывайте каскад целиком и не дублируйте одно свойство в нескольких файлах: у каждого свойства одного элемента должно быть одно «владеющее» место (см. ниже). Переносите стиль из `style={{ … }}` в CSS — инлайновое значение удаляйте.

## Где править

| Что менять | Где |
| --- | --- |
| Цвет, который должен быть разным в темах | Переменная в `themes.css` (блок `:root, [data-theme="claude"]` и блок `[data-theme="custom"]`); правило использует `var(--имя)`. |
| Сырая палитра, шрифты Finch Custom | `custom-tokens.css`. |
| Размер, отступ или начертание, одинаковые в обеих темах | `themes.css`, общее правило без префикса. |
| Размер или начертание только Finch Custom | `themes.css`, правило с `[data-theme="custom"]`. |
| Положение и поведение элемента (позиция, прокрутка, видимость при наведении) | `app.css`. |
| Минимум, прокрутка или перенос для узкого окна и крупного текста | `polish.css`. |
| Базовый размер компонента «по макету» | `finch.css`; менять его только если нужно изменить и макет (запись в `docs/design-deviations.md`). |

Перед правкой найдите все правила для селектора: `grep -n "\.daysep" src/styles/*.css`. Если свойство задано в нескольких файлах, правьте то, которое реально действует (самое специфичное, а при равенстве — самое нижнее по списку).

## Как добавить правило для одной темы

1. Выберите владеющий файл: размеры и отступы тем лежат в `themes.css`.
2. Запишите общее правило для обеих тем, если оно есть, и отдельную строку для Finch Custom:

```css
.daysep { padding:24px 28px; font-size:12px; /* … */ }
[data-theme="custom"] .daysep { text-transform:uppercase; font-size:11px; letter-spacing:.08em; }
```

3. Свойства, которые у Finch Custom должны остаться прежними (верхний регистр, разрядка, моноширинный шрифт), не меняйте и не повторяйте без нужды.
4. Для Claude Dark отдельного префикса не нужно: его значения — это общие правила и блок `:root`.

## Как проверять

Тесты не видят настоящую вёрстку: happy-dom не считает размеры и не применяет каскад. Поэтому проверка двойная.

**Автоматически** (`cd app/frontend && npm test`): `src/styles/*.test.ts` читают файлы стилей с диска и проверяют, какое значение действует в каскаде (`styles/cssTest.ts` — общие помощники). Такой тест фиксирует решение, но не заменяет взгляд на экран.

**Руками** в приложении, для каждой правки:

1. **Обе темы.** «Внешний вид → Тема»: Claude Dark и Finch Custom.
2. **Размер текста.** «Маленький», «Средний», «Большой»: ничего не обрезано и не наезжает друг на друга.
3. **Узкое окно.** Минимальный размер окна — 900×600 (`app/tauri.conf.json`). Проверьте 900×600, 1000×650 и 1280×720: на границах 1150, 940 и 720 px меняются ширины панелей, на ≤940 px панель участников скрыта.
4. **Язык.** Русский текст длиннее английского: переключите язык и посмотрите, как ведёт себя правка.
5. **Роль.** Часть элементов видна только администратору (действия канала); проверьте из-под администратора и обычного участника.

## Примеры из практики

**Панель участников не прокручивалась** (`fix(ui): scroll the members panel`). Свойства прокрутки колонки относятся к поведению, поэтому правило лежит в `polish.css`: `.members { min-height:0; overflow-y:auto; scrollbar-gutter:stable; … }`. В `finch.css` и `themes.css` для `.members` прокрутку не задают — тест следит, чтобы нижние слои её не сбрасывали.

**Окна над полем ввода перекрывали его край** (`fix(ui): anchor composer popovers above the input`). Выбор эмодзи и список упоминаний стояли на фиксированных `bottom: 72px`, а высота поля зависит от темы, числа строк, плашки ответа и вложений. Теперь поле обёрнуто в `.composer-anchor { position: relative }`, а всплывающие окна используют `bottom: calc(100% + 8px)`: они всегда на 8 px выше верхнего края поля. Правило положения — в `app.css`, у владельца раскладки.

**Разделители дней были слишком мелкими** (`fix(ui): enlarge day separators in both themes`). Базовое правило `.daysep` в `finch.css` (11 px) перекрывается правилом `themes.css` для обеих тем, поэтому размеры задаются там: 12 px у Claude Dark, 11 px у Finch Custom (правило с `[data-theme="custom"]`, верхний регистр и разрядка сохранены). Базовую строку в `finch.css` не трогали: она не действует.

**Действия канала сжимали название** (`fix(ui): keep channel names visible next to admin actions`). Раньше кнопки при наведении вставали в строку рядом с названием и оставляли ему 3–4 символа. Теперь `.ch .acts` в `app.css` — абсолютно позиционированный блок справа с `background: inherit`: он закрывает правую часть строки цветом самой строки (фон наведения, активный канал, тема). Пока фокус внутри строки, она получает фон `var(--bg-hover)`, чтобы подложка не была прозрачной. Полное название лежит в `title`.
