# Повторный аудит безопасности (этап 7, 2026-10-16)

Что проверено: сервер (REST и QUIC), клиент (Tauri, интерфейс), зависимости. Метод: чтение нового кода этапа 7, тесты на злоупотребление, `cargo audit` (база RustSec от 2026-10-16), `npm audit`. Всё, что найдено, исправлено с тестом, кроме пунктов в разделе «Принятые риски».

## Финальная проверка перед 1.0.0

`cargo audit --no-fetch --no-yanked --json` показывает только уязвимость `rsa`
и предупреждения о зависимостях из таблицы принятых рисков. `cargo tree -i rsa`

завершилась тайм-аутом; она не объявляется успешной.

Actions secret; в репозиторий и отчёты приватный ключ не включён.

## Принятые риски

| Что | Почему принято |
|---|---|
| `rsa` 0.9 (RUSTSEC-2023-0071, атака Marvin), исправления нет | Только в `Cargo.lock` через `sqlx-mysql`; для SQLite в сборку не входит (`cargo tree -i rsa` пусто) |
| `atty` (RUSTSEC-2024-0375, 2021-0145), `proc-macro-error` — не поддерживаются | Приходят через `nnnoiseless` → `clap 3` (аргументы командной строки, которые мы не используем) и макросы времени сборки; в нашем коде не вызываются |
| `audiopus_sys` не поддерживается (RUSTSEC-2026-0150) | Привязка к libopus; замены нет, формат Opus нужен; уязвимостей в самой привязке не заявлено |
| `glib` 0.18 (RUSTSEC-2024-0429) | Только Linux-часть Tauri; в Windows-сборку не входит |
| `tauri-plugin-updater` не используется | Его зависимость `zip` 2.x/4.x отозвана в реестре: плагин не собирается. Заменён собственным модулем (S-12) |
| Закрытый ключ обновлений создан без пароля | Ключ лежит вне репозитория (`C:\Users\Михаил\finchspeak-secrets\updater.key`), передаётся владельцу; владелец может создать свой ключ с паролем: `tauri signer generate`, заменить `app/src/update_key.pub` и секрет `TAURI_SIGNING_PRIVATE_KEY` |
| Сертификат сервера самоподписанный (проверка по отпечатку при первом подключении) | Решение владельца; предупреждение о смене сертификата и ввод имени сервера для подтверждения |
| Установщик без подписи Authenticode | Решение владельца; SmartScreen покажет предупреждение (описано в README) |
| CORS открыт для любого источника | Токен передаётся заголовком `Authorization`, куки не используются: чужая страница не может сделать запрос от имени человека |
| Файлы доступны любому вошедшему по идентификатору (UUID) | Каналы общие, закрытых нет; идентификатор не угадывается |
