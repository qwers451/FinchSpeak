# Проверка выпуска FinchSpeak 1.0.0

Дата: 2026-10-16. Цель: Windows-релиз для последующей приёмки владельцем на двух ПК.
Проверки проведены на Windows на одной машине; результаты не доказывают качество
реального интернет-канала, микрофонов и колонок на другой машине.

Нагрузка: голос 294294/294294, видео 18036/18036, чат 5000/5000;
задержка чата p50/p95/max 20/63/68 мс. Сервер и 50 headless-клиентов в одном
процессе на localhost, синтетические медиапакеты. Подробности в
[BASELINE.md](../crates/finch-testbed/BASELINE.md).

Проверка отозванных Rust-пакетов через реестр завершилась тайм-аутом и не
записывается как успешная. Уязвимость `rsa` в lockfile и предупреждения о
неподдерживаемых зависимостях перечислены в [повторном аудите](audit/2026-10-security-recheck.md).

## Настоящий клиент

Запущен собранный `target/release/finch-app.exe`, встроенный интерфейс корректно
отрисовался в WebView2. Проверены диалог первого доверия TLS, совпадение SHA-256
с сертификатом тестового сервера, вход, загрузка каналов и отправка сообщения.
Сохранение сообщения подтверждено отдельным REST-запросом к истории сервера.
Дополнительно запущены два настоящих клиента с отдельными WebView-хранилищами:
оба вошли в голосовую комнату; второй получил историю чата, увидел LIVE-карточку
первого и декодировал его экран 1920×1080 (на момент проверки HUD: 25 FPS).
Проверено выключение микрофона второго клиента. Качество звука на слух
и звук экрана в наушниках не проверялись.
Рабочие аккаунты и БД владельца не использовались: отдельный сервер и тестовые
пользователи в `target/release-smoke-*`.

По пути найден и закрыт регресс `localhost`: DNS выбирал `::1` для IPv4 QUIC-
сокета. Оба резолвера теперь предпочитают IPv4, если он доступен; добавлен тест
реального соединения. IPv6-only серверы в этом выпуске не поддерживаются.

## Исправления финального ревью

- Атомарное удаление старых непривязанных загрузок через `DELETE … RETURNING`:
  файл, не удалённый из БД, остаётся на диске.
- Ограничены длина логина и память защиты от перебора паролей; новые ключи при
  заполнении отклоняются до проверки пароля; истёкшие записи освобождаются.
- Закрыты замечания Clippy, из-за которых предыдущие CI завершались ошибкой.
- Проверки в CI/release fail independently: последующая успешная команда не
  скрывает ошибку теста, сборки, подписи или проверки манифеста.
- В серверный ZIP добавлен launcher, инструкции соответствуют составу файлов.
- Первый чистый CI выявил нестабильность сетевого голосового теста: тяжёлые
  корреляционные проверки шли одновременно с аудио по настенным часам. Их
  вынесли в отдельный бинарник, сетевому тесту выделили два Tokio workers,
  добавили диагностику опоздания тиков и длительности DSP. CI/release запускают
  Rust-тесты с `--test-threads=1`, сохраняя все проверки и исходные пороги.
- Дополнительный прогон при небольшом опоздании таймеров обнаружил две реальные
  ошибки jitter buffer: отрицательная разница времён переставленных пакетов
  трактовалась как огромная положительная; обычное поступление нового пакета
  могло перескочить через потерянный кадр, сжимая временную шкалу. Обе ошибки
  воспроизведены отдельными падающими тестами и исправлены; проверка переполнения
  временной метки сохранена. После исправлений три пробы дали около 96 мс,
  максимальный буфер 5 пакетов, без последовательной тишины.
- Независимое code review: блокирующих замечаний после исправлений нет.

## Оставшаяся приёмка владельца

[RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md): два ПК, интернет/NAT, реальное
качество голоса и звука экрана, чистая Windows, установка/удаление и последующее
обновление на вторую опубликованную версию. Docker здесь не проверялся.

GitHub CI и release workflow повторяют проверки на чистом runner, проверяют
архив и реальную подпись перед публикацией. Итоговый статус конкретного запуска
смотреть в GitHub Actions. Приватный ключ хранится вне репозитория и в secret.
