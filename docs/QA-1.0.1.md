# Повторная QA-проверка релиза

Дата: 2026-10-17, Windows x64. Повод: сервер 1.0.0 не запускается у владельца
после распаковки ZIP и запуска `Run_Server.bat`.

## Исходный инцидент

Проверены опубликованные GitHub Release assets и скачанный владельцем архив.
SHA-256 серверных ZIP совпадает. Найдена фактическая распаковка на
`E:\FinchSpeak-server-windows`, а также portable-копия на `E:\FinchSpeak-windows`.
Перед запуском первой сделана полная резервная копия в
`target/release-validation/user-start-cc18ef73ff3c47ebbf4fbcfe6835354e/before`.
Рабочие конфиги, сертификаты, секреты и база не заменялись.

Старые журналы трёх запусков заканчиваются после чтения сертификата, до строки
о готовности QUIC. Причины отказа в них нет. При повторной проверке оригинальный
EXE из папки владельца ответил `/health`: `status=ok`, `version=1.0.0`.
Таким образом, точная причина исходного инцидента **не установлена**: постоянный
отказ на этой машине сейчас не воспроизводится. Отсутствие VC++ runtime нельзя
объявлять причиной именно этого инцидента — на этой машине DLL присутствует.

## Подтверждённые дефекты и исправления

| Приоритет | Доказательство | Исправление и регрессия |
|---|---|---|
| P1: непереносимый серверный ZIP | PE опубликованного EXE импортирует `VCRUNTIME140.dll`; DLL отсутствует в ZIP. Новый тест отвергает старый EXE. Без установленного runtime Windows не дойдёт до Rust `main`. | Отдельная server-only сборка с `+crt-static`; фактический PE нового EXE проходит проверку. Проверка повторяется после извлечения ZIP. |
| P2: причина остановки не попадает в файл | Занять TCP 8443, запустить BAT: stderr содержит `Failed to bind HTTP listener`, файл лога — нет. Регрессионный тест сначала упал. | Полная цепочка ошибки `launch` пишется в файловый лог до возврата из `main`; процессный тест проходит. |
| P2: неясный отказ неполной распаковки | Запуск одного BAT без соседнего EXE: системное «command not recognized», код 9009; исходный launcher-тест упал. | Сообщение `Extract ALL files`, код 2; код завершения реального сервера также сохраняется. |
| P2: недостаточный релизный smoke | Прежний скрипт заменял конфиг и запускал EXE напрямую. Зелёный CI не доказывал работу BAT или переносимость на чистую Windows. | Дополнительный процессный тест настоящего launcher/конфига обоих ZIP; проверка DLL, TCP/UDP конфликтов, повреждённых настроек и TLS. |
| P3: ложная ошибка первого старта | При отсутствующей папке логов `tracing-appender` сначала пытается удалить старые логи, печатает `Error reading the log directory/files`, затем создаёт папку и работает. Дополнительный процессный тест чистого запуска сначала упал. | Каталог создаётся до инициализации ротации; оба ZIP проходят проверку без ложной ошибки. Ошибка создания каталога по-прежнему включает штатный fallback на console-only. |

При `RUST_LOG=warn` успешный старый сервер мог не показывать ни одной строки
после первого запуска. Добавлен независимый от фильтра логов статус `ready`,
адреса и отпечаток сертификата. Фильтр подробных диагностических логов сохранён.

--workspace --all-targets`, `cargo clippy --workspace --all-targets -- -D warnings`

публичным ключом, изменённый установщик отклонён. Все новые процессные проверки
launcher/API прошли на server-only и portable архивах.

Стандартные настройки/порты проверены до запуска серверной копии владельцем.
Расширенные отрицательные сценарии затем повторены на тестовых портах
58443/54433, чтобы не мешать его работающему серверу. В CI используются
неизменённые порты и конфиг из архива. Финальный независимый review не нашёл
блокирующих замечаний. Публикация 1.0.1 должна повторить проверки на GitHub runner;
затем следует перепроверить именно скачанные assets.

## Пределы результата

Два реальных ПК, интернет/NAT/настройки маршрутизатора, качество микрофона и
колонок на слух, установка на Windows без инструментов разработки и полный
цикл автообновления требуют отдельной приёмки. Установка/удаление проверены
на текущей машине, где WebView2 уже установлен. Удаление
системных DLL для имитации чистой Windows не проводилось. Docker недоступен.
IPv6-only серверы не поддерживаются. Это не помечается как пройденные проверки.
Список ручных сценариев: [RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md).
