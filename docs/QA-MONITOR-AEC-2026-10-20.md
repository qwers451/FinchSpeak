# Исправление опорного сигнала локального мониторинга

Основание — реальные отчёты ветки `codex/audio-investigation-reports`, коммит `4f6d81c`: на HS5 нормальный отложенный тест, прерывистое самопрослушивание; 48 кГц / stereo / F32, callbacks 10 мс, нулевые зарегистрированные потери очередей. На нашей машине повторены все 10 опубликованных AEC-контролей на DLL с SHA256 `d30128d0a9f6c94592a5ff03cf9eb432d6ff3fc835a3b991ee7cc9f55af8083d`; сводные результаты совпали. Это подтверждает модель, не конкретное поведение HS5.

## Воспроизведение через VoiceCapture

Добавлен регрессионный прогон настоящих AEC → RNNoise → gain на речевой фикстуре, где выход мониторинга возвращается в render reference с задержкой. Исходная маршрутизация не совпадает с контрольной обработкой без мониторинга: максимальная разница отсчётов 0,64333403 при задержке 60 мс. Лог падающего теста: `target/audio-network-qa/monitor-feedback-red.log`. Разница PCM — доказательство влияния маршрута, не MOS и не сама по себе оценка роботизации.

Исправленная маршрутизация проверяется с задержками 60/120 мс, улучшением on/off, свежим AEC и после 100 кадров удалённой речи с последующим затиханием (sticky has_reference уже установлен). Во всех восьми комбинациях мониторинг не меняет контрольный обработанный PCM с допуском 1e-6. Проверка не включает драйвер и акустический путь HS5.

## Изменение

Из AEC reference исключён только **непрерывный live monitor**. Записанный MicTest, голос собеседников и звук экрана остаются в reference. Решение с исключением также MicTest отклонено после независимого ревью: оно не улучшает уже записанные кадры и убирает опору при их акустическом воспроизведении. Логика приватности теста и момента открытия gate в этом изменении не меняется.

Выход передаёт `PlaybackSample { audible, echo_reference }` одним элементом lock-free кольца. Два mono ресемплера работают на каждом кадре с одинаковым ритмом, включая нулевые кадры и хвост после выключения мониторинга; при ошибке совместно пересоздаются. При clipping audible ограничивается, а reference сохраняет соответствующий масштаб исходного remote/test mix. Callback выводит audible и передаёт в reference только echo_reference. Underrun/deafen дают нули. Глобального выключения AEC нет.

Положительные контроли: reference удалённого/тестового звука сохраняется; подавление удалённого эха остаётся активным. При 16/44,1/48/96 кГц проверены соответствие длин, monitor on → off и отсутствие его FFT-хвоста в reference. Отдельно проверена фактическая функция callback-вывода с stereo, own/remote mix и underrun.

Через динамики live monitor может акустически вернуться в микрофон. Сохраняется существующее требование использовать наушники для самопрослушивания; для обычного голоса через динамики reference сохраняется полностью. Изменение не обещает исправить все особенности гарнитур и драйверов.

## Диагностика при сохранении симптома

Opt-in отчёт дополнен агрегатами мощности на входе mono, после AEC, RNNoise и усиления, количествами спадов более 12 дБ при активной предыдущей стадии и максимальными последовательностями таких кадров. Индексы кадров не выравниваются по задержке DSP: отдельные спады могут быть нормальными переходами речи. Доступны также изменения transmission privacy gate и успешные DSP-reset при его повторном открытии, накопленные с начала текущего capture stream. Для иных reset-источников этот счётчик не предназначен.

PCM не сохраняется; расчёты мощности включаются только при ручной диагностике. Новые тесты подтверждают неизменность обработанного PCM и пакетов при переключении диагностики. Сборщик сохраняет ограничение истории, epochs и явные поколения устройств.
