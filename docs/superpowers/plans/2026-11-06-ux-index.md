## Как исполнять (subagent-driven, воркеры на Haiku)

- Навык: `superpowers:subagent-driven-development`. Одна задача — один свежий воркер `model: haiku`, затем один ревьюер `model: haiku` (соответствие плану и тесты). Финальное ревью каждой ветки целиком — один раз на Opus.
- **Экономия токенов:** воркеру передаётся только текст его задачи, а также разделы Global Constraints и Review Focus его плана, без всей переписки. Он читает только перечисленные в задаче файлы. Сборку Rust (`finch-app`) делать с `FINCH_WEBRTC_ROOT`, а длинные команды (`cargo test --workspace`) запускать в фоне. Отчёт воркера — до 15 строк: что сделано, вывод тестов, коммит.
- **Где Haiku может не справиться:** план 2, задача 2 (COM/WASAPI). Если ревью дважды не прошло, повторить задачу на Sonnet. Остальные задачи по объёму рассчитаны на Haiku.
- Ручные проверки (на слух, перезагрузка ПК, установщик) воркеры не выполняют: они записывают их в `docs/audit/manual-voice-checklist.md`, и пользователь проходит их по готовности ветки.
- Пуш и PR — только с подтверждения пользователя.
