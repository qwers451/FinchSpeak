# FinchSpeak 1.1.0: WebRTC APM + RNNoise

Дата: 2026-10-17. Статус: выбранная владельцем архитектура; конкретные контракты ниже представлены вместе с планом для итогового согласования. Это не отчёт о выполнении.

## Цель и границы

Естественная, разборчивая разговорная речь: тихого участника слышно, громкие пики ограничиваются, эхо и фон подавляются, начала слов сохраняются. Приоритет владельца — качество уровня современных голосовых клиентов и минимум собственных DSP-алгоритмов. Побитовое или субъективно идентичное звучание Discord/TeamSpeak не обещается.

Целевая поставка — стабильный Windows x64 v1.1.0, установщик, portable-пакет, серверный ZIP и подписанное автообновление. Исполнитель реализует сам в текущем чате; в конце один независимый reviewer. Существующие разрешения на Git/push/релиз и ключ подписи сохраняются. Пока владелец согласует этот документ и план, продуктовый код не меняется.

## Что заменяет этот документ

Предыдущий план `../plans/2026-10-17-voice-enhancement.md` описывал собственные AGC/компрессор/лимитер. Его DSP-реализация и параметры больше не являются целевой архитектурой. Ветка `codex/voice-enhancement` содержит три незарелизенных коммита 373142e, 6156d3a, cf4ac96; их полезные настройки/проверки приватности сохраняются через обычные последующие коммиты. История не переписывается, опубликованные v1.0.0/v1.0.1 не изменяются.

Отменяются требования к собственной кривой ratio/knee/attack/release, RMS target -22 dBFS, ослаблению -12 → -18 dBFS и сближению до 8 dB за 3 секунды. Они описывали конкретный самописный компрессор; AGC2 не является тем же компрессором. Вместо них ниже определены проверки поведения готового AGC2. Выпущенные критерии AEC/NS/VAD/сети не ослабляются.

## Библиотеки и поставка

- Оригинальный C++ WebRTC APM: AEC3, AGC2, встроенный limiter. Sonora и самописный `VoiceDynamics` в релизный тракт не входят.
- RNNoise сохраняется через существующую готовую библиотеку `nnnoiseless` и её встроенную модель, в точной версии из Cargo.lock. Это Rust-порт RNNoise, не новая собственная реализация и не утверждение об использовании самой новой C-модели Xiph. Обновление модели/переход на C RNNoise не входят в эту миграцию.
- Earshot остаётся детектором открытия сетевой передачи; внутренний VAD AGC2 оценивает gain. Это разные задачи: второй не может открыть пользовательский порог/PTT.
- Приоритет подключения WebRTC — готовая обёртка `tonarino/webrtc-audio-processing`, только если её конкретная версия проходит native Windows MSVC и CI. Чтение её build.rs обнаружило Unix-oriented сборку; поддержка MSVC не считается проверенной.
- Если обёртка не проходит Windows, используется оригинальный WebRTC через штатную GN/Ninja-сборку и небольшой C ABI adapter. Адаптер владеет объектами/буферами и вызывает upstream API; не переносит и не модифицирует DSP.
- На первом этапе выбирается и фиксируется ровно один путь. Fallback на Sonora/свой DSP, изменение алгоритмов upstream или неофициальные бинарники не допускаются без согласования.
- Ревизии всех исходников/DEPS/toolchain и контрольные суммы фиксируются в `native/webrtc/dependencies.lock.json`. Точная ревизия выбирается при нативной проверке совместимости, до подключения к продукту. Нельзя скачивать плавающий main во время последующих сборок.
- Все нужные бинарные компоненты входят в поставку; DSP не требует сети, плагинов, Python, компиляторов или виртуального микрофона у пользователя. Python/GN/Ninja/LLVM допустимы только как инструменты сборки.
- Лицензии/NOTICE/PATENTS WebRTC, RNNoise и транзитивных библиотек включаются в документы и пакеты; содержимое модели и её условия учитываются.

## Тракт и точки встраивания

Формат FinchSpeak сохраняется: mono 48 kHz, 960 samples/20 ms, прежний Opus 64 kbit/s и MediaHeader. Внутри два последовательных блока 480 samples/10 ms.

Поток: sanitized input → WebRTC AEC3 → RNNoise → анализ пользовательского threshold/Earshot → WebRTC AGC2 + limiter → pre-roll/Opus. Фактический render reference подаётся только AEC3; screen-share audio не пропускается через микрофонную обработку.

Чтобы RNNoise находился между AEC3 и AGC2 без изменения WebRTC, adapter владеет двумя экземплярами APM: AEC-only и AGC-only. Во втором AEC/NS/high-pass выключены; в первом AGC/NS выключены. Дополнительная очередь кадров не вводится. Состояния и буферы создаются при открытии источника; processing вызывается только из audio worker. Повторные setters с тем же значением не применяют Config заново и не сбрасывают AEC.

При смене микрофона/сеанса все адаптивные состояния, частичные блоки и pre-roll пересоздаются. Переполнение far-end reference сбрасывает только AEC, а не AGC/RNNoise. На переключении enhancement пересоздание AEC/устройства запрещено.

## Ручная громкость, профиль и переключение

- `Input volume` остаётся 0–300% в UI; backend защищает существующий диапазон 0–8. Ноль даёт точный ноль.
- AEC/NS получают исходный нормализованный сигнал. Вход NaN/Inf заменяется нулём, слишком большой raw PCM ограничивается диапазоном [-1,1] до библиотек.
- VAD/meter получают отдельную копию `clamp(post_ns * input_gain, -1, 1)` до AGC. Это сохраняет влияние ручной громкости на пользовательский порог.
- Для enabled-тракта `gain < 1` применяется к нормализованному входу AGC2; `gain >= 1` передаётся через поддерживаемый fixed digital gain AGC2 (20*log10(gain)) до его limiter. Не подавать samples с запасом ±8 в API, документированный для [-1,1]. Fixed gain меняется штатной runtime-настройкой; при её отсутствии на выбранной ревизии — только AGC-only Config на реальном изменении значения.
- Профиль-кандидат: adaptive digital enabled; input/analog volume controller disabled; initial adaptive gain 0 dB; max adaptive gain +12 dB; max gain change 6 dB/s; max output noise -50 dBFS; headroom 6 dB; fixed digital gain 0 dB при ручных 100%. Системная громкость микрофона не меняется.
- Для естественности разрешена настройка только штатных параметров: headroom 5–12 dB, adaptive rate 3–6 dB/s, output noise -55…-45 dBFS. Max adaptive gain +12 dB не повышается. Ручной boost учитывается отдельно и документируется. Ни одного дополнительного собственного компрессора/gate/автоэквалайзера.
- После штатного limiter — постоянное масштабирование -1 dB, чтобы сохранить согласованный цифровой запас. Это не новый адаптивный limiter. Все enabled samples finite и peak ≤0.891251 +1e-6.
- `voice_enhancement=false` обходит новый AGC/limiter, AEC/RNNoise остаются. Manual trim в этом режиме ограничивается [-1,1]. Включение/выключение сглаживается за 20 ms только смешением dry/wet, без очереди; fully-off допускает peak 1.0. При включении с громкого dry-сигнала потолок достигается к концу переходного кадра; это исключение явно тестируется, а не скрывается hard clip в начале fade.
- Внутренний AGC2 сам оценивает речь и фон. Не добавлять вокруг него собственный контроллер gain или второе условие адаптации, конфликтующее с upstream. На паузах gain/noise проверяются измерениями; отсутствие роста внутреннего gain побитово не обещается.

## Сетевой контроль и UX

Один default-on `Voice enhancement` в `Voice and audio`, текст `Balances quiet and loud speech and limits peaks.`

Отсутствующее поле старых сохранений/DTO означает true; явное false сохраняется. Ошибка backend оставляет предыдущие UI/storage. Сохраняются Input volume, Speech threshold, PTT/key, Test microphone и Hear myself. Индикатор соответствует порогу до AGC; hint объясняет, что усиление не открывает речь ниже порога.

Закрытый PTT, mute, mic test и выход из комнаты очищают сетевой pre-roll. После открытия нельзя посылать звук, захваченный в приватном состоянии. В mic test/monitor поступает конечный обработанный PCM. Обычные 80 ms pre-roll и 100 ms hangover, silence flag, последовательность/timestamps сохраняются.

Новый capture error не выпускает raw/private frame в сеть. Ошибка инициализации/устойчивый processing failure возвращаются клиенту как понятная ошибка микрофона, а не молчаливое отключение enhancement. Только принадлежащие тесту процессы/каталоги останавливаются/меняются.

## Проверки и критерии релиза

1. Build: native x64 MSVC debug/release, локальный и чистый GitHub Windows runner, cache miss/hit. Один выбранный upstream/toolchain lock; новые C++ DLL отсутствуют или необходимые разрешённые runtime-файлы явно входят в пакет. Никаких отсылок пользователя устанавливать SDK.
2. Adapter: 960→2×480→960; safe ownership/reset/drop; многократные create/drop, тишина, ноль trim, nonfinite/extreme PCM/reference, смена задержки/reference, переключения и injected failures. После warm-up adapter не аллоцирует и не делает I/O в обработке.
3. AEC: прежний ERLE ≥20 dB после convergence; near-end loss при double-talk ≤6 dB. Проверять изолированный компонент и полный enabled-тракт.
4. NS: прежний прирост SNR ≥10 dB на white/pink, segmental out≥in в отдельном AEC/NS control без AGC. Babble только измеряется. Дополнительно full enabled A/B с теми же voiced-окнами и gain-calibrated метрикой; усиление речи относительно отдельной паузы не считать приростом шумоподавления. Старую функцию metrics не переписывать ради pass.
5. Leveling: три speech fixtures, одинаковые окна, уровни -38/-26/-12 dBFS, 15 s повторения; статистика последних 5 s после ровно 10 s адаптации. Где loud scaling уже клиппирует source, входное clipping отдельно фиксируется. Default-on даёт тихому -38 минимум +6 dB относительно off; разброс выходных уровней сокращается минимум на 6 dB относительно off. Громкий settled output не выше off более чем на 3 dB. Не удалять пропущенные VAD слова из сравнения. Эти пороги заменяют только невыпущенные custom-DSP критерии выше.
6. Паузы: speech→stationary noise→silence→speech; шум в последней секунде 2-секундной паузы не выше первой полной секунды более чем на 3 dB; цифровая тишина/trim0 остаются нулём; нет VAD-пакетов на pink -35/white -45 dBFS. Увеличение фона за пределом — не pass, профиль исправляется штатными параметрами.
7. VAD/privacy: начала трёх speech fixtures не хуже Energy-VAD onset с pre-roll; hangover и FLAG_SILENCE сохранены; ни одного private timestamp/sample в поздних пакетах; mic test/monitor используют выбранный режим.
8. Latency: прежняя обычная end-to-end ≤120 ms; impaired 5% loss +0–60 ms jitter ≤200 ms для каждого из трёх probes, jitter buffer ≤6, consecutive silent frames ≤3. Новая очередь DSP =0; диагностируются max/p95 capture time и 30 min soak, bounded memory и отсутствие разрывов.
9. Приложение/совместимость: все Rust/TS checks; реальные клиенты/опубликованный сервер 1.0.1 и новый 1.1.0, чат, QUIC voice обе стороны, mute/PTT, mic test, reconnect/device change, screen audio. Два клиента на одном ПК не считаются двумя физическими ПК.
10. Release: полный regression, load50, независимое итоговое ревью и исправления, fresh install/upgrade 1.0.1→1.1.0, оба ZIP/Run_Server.bat, updater signature и tamper rejection, GitHub CI + Release success, повторная проверка скачанных assets и public latest.json.

Отчёт различает PASS/FAIL/NOT RUN/OWNER CHECK. Прослушивание человеком на двух ПК, акустика реальных микрофонов, NAT/маршрутизатор и чистая Windows при недоступности среды остаются явно отмеченной приёмкой владельца. Они не подменяются автоматическими метриками. Стабильный релиз разрешён после всех доступных обязательных проверок; неизвестный алгоритм/блокирующий regression — причина не публиковать.
