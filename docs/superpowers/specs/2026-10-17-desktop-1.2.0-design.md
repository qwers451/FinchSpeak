# FinchSpeak 1.2.0 desktop design and microphone fixes

Owner approved autonomous implementation and stable GitHub publication on 2026-10-17. No additional design/plan confirmation is required. Existing signing authorization remains valid.

## Outcome
One SolidJS/Tauri application, two complete dark themes with identical features. New and migrated profiles default to Claude Dark; users may choose Finch Custom and their choice persists. Russian is the default with persistent English selection. Keep application data and server compatibility.

## Visual contract
Claude Dark: warm charcoal (#262624 ground, #20201e rail, #30302e floating surface), warm ivory text, restrained clay accent (#d9987e), generous but useful space, rounded interactive shapes, refined typography. Main experience remains channel navigation + chat/voice + optional members, with polished welcome, authentication, trust, settings, admin, sharing and error/empty/loading states. Never redesign into an AI chatbot.
Finch Custom: reproduce supplied finchspeak-ui-kit rev2 identity: cut corners, opaque navy panels, cyan/amber/ignition accents, JetBrains Mono for compact UI and Inter for prose, kit brand/icons/tray/illustrations. Adapt classes to existing Solid components instead of rewriting framework. No fake telemetry or ornamental spectra that imply measured audio. Existing functionality remains reachable in both themes.
Motion uses Design Motion Principles: Emil primary for frequent controls, Jakub secondary for production finish, Jhey selectively for custom empty states. Enter/exit dialogs, menus, toast and panels smoothly; never delay typing, mute/PTT or audio capture. Respect OS and application reduce-motion preference; stop unnecessary background animation.

## Features and limits
Carry existing real chat, search, replies, edit/delete, reactions, attachments, members, voice, screen sharing, trust, invites, roles and audit into both designs. Add theme/language selection and kit tray states where backed by actual application state. Use existing registration/role semantics. Do not introduce new roles, cryptographic audit chains, speculative CPU labels, or unsupported video configurations from demonstration data. Autostart, new permission systems and hardware decoder switches are deferred: production reliability and minimum complexity have priority. Keep one voice enhancement switch and existing controls; do not add separate RNNoise/AEC/AGC controls.

## Audio contract
Microphone test suspends effective live monitoring while active without changing the saved Hear myself preference. Restore on completion/cancel/failure; changes the user makes during test remain authoritative. Monitoring and mic test must not mix. Add a truthful local activation preview obeying the actual VAD + threshold + PTT policy; keep processed-preview/activation semantics explicit and network privacy closed during tests. No private samples or codec/preroll history can enter public voice after the test. Meter displays measured level and actual speaking decision separately. Existing RNNoise/WebRTC DSP remains unless evidence requires change; do not claim natural timbre improvement without recordings.

## Localization
All shipped client screens, labels, tooltips, validation, local feedback and diagnostics explanations support Russian/English. User/server supplied content, identifiers, certificate hashes, logs and OS errors remain verbatim. No DOM text-replacement observer; use explicit reactive translation at render sites and interpolation for dynamic strings. Migrate missing/invalid locale to ru and theme to claude. Localize dates/numbers with selected locale where displayed.

## Verification and release
Behavior tests for preference migration/persistence/live switching, translation coverage, simultaneous monitoring and test lifecycle, actual activation preview, private-to-public transitions. Existing frontend and Rust suites, typecheck/build/clippy. Real browser screenshots both themes: auth, chat, voice, settings, admin, sharing; small and large windows, keyboard focus and reduced motion. Run release/package/server smoke tests, inspect installer/portable/server licenses, verify updater signature and SHA256. One independent whole-branch review and fix important findings. Version all manifests to 1.2.0, merge/push main and annotated v1.2.0 after green checks, watch release workflow and verify actual published assets. Preserve v1.1.0 tag.
