# Закрытие открытых находок HANDOFF

Владелец запросил исправление всех багов `docs/HANDOFF.md`, запретил предположительные исправления и разрешил установку необходимых инструментов. После согласования первого блока фронтенда отдельно разрешил все необходимые исправления без дальнейшего согласования дизайна и планов. Новые возможности из дорожной карты, не нужные для исправлений, не входят в работу. E2EE не добавляется.

## Уже проверенные причины

- Фронтенд смешивал `id` и `message_id`, переворачивал хронологическую историю и не импортировал функции. События Rust не были полностью подключены. Участники всех комнат хранились общим списком.
- Повторные сессии пользователя теряли индекс при выходе одной из них. Проверка «первый пользователь — администратор» не была атомарной. JWT не проверял существование серверной сессии.
- История делала запрос вложений для каждого сообщения; UDP-прокси прекращал приём после Windows `10054`; сетевой тест проверял только начальную задержку.
- Старый AEC имеет окно поиска 64 отсчёта (1,3 мс), не работает при тестовой задержке эха 40 мс. Приложение подаёт эталон до очереди воспроизведения, а не фактически выведенный сигнал.
- RNNoise действительно возвращает высокую вероятность речи для тестового розового шума. Подстановка порога 0,5 не является доказанным исправлением AUD-050.

## Интерфейс и жизненный цикл

Внутри фронтенда сообщения имеют `id`; транспорт преобразуется на входе. История и живые события объединяются без потери сообщений, повторов подтверждений и обратного порядка. Подписки устанавливаются до входа и очищаются даже при асинхронном завершении после размонтирования. Снимок `/api/state` с авторизацией восстанавливает каналы, профили и голос; Tauri дополняет его локальным peer ID, mute/deafen и выбранной голосовой комнатой. События, пришедшие во время снимка, применяются повторно поверх него.

Logout отзывает только текущий JWT и закрывает соединения с этим токеном. Вторая независимая сессия сохраняется. Локальный выход выполняется и при сетевой ошибке; невозможность удалённого отзыва показывается явно. Замена QUIC-сессии закрывает старое соединение; поколение сессии запрещает старым обработчикам запускать новое переподключение.

## Аудио

AEC сохраняет внешний формат 48 кГц mono / 20 мс, внутри использует Sonora 0.2.0 AEC3 блоками по 10 мс. Дополнительные NS/AGC Sonora не включаются поверх существующего шумоподавления. Звук фактического callback вывода (включая тишину при deafen/underrun) поступает в ограниченную lock-free очередь, преобразуется обратно в 48 кГц в рабочем потоке и передаётся AEC по порядку. Колбэки не выделяют память и не берут мьютексы. Переполнение и смена устройства сбрасывают устаревшее состояние AEC.

Выбор устройств применяется к действующему голосовому соединению без выхода из комнаты. Ошибка отключённого устройства видима; рабочий поток повторно открывает выбранное доступное устройство либо устройство по умолчанию с явным уведомлением. Нативные частоты и формат samples проверяются при открытии.

VAD должен отличать шум от речи на имеющихся fixtures и сохранять положительную проверку реальной речи. Дискриминатор выбирается после измерений, а не подгонки произвольного порога. Тесты измерения транспорта могут явно отключать VAD для искусственных чирпов; пользовательский голос всегда использует реальный режим.

## REST TLS и TOFU

REST работает по HTTPS с тем же сохраняемым сертификатом, что QUIC. До отправки пароля выполняется TLS-проверка без учётных данных. Новый или изменённый отпечаток требует существующего окна TOFU; подписи TLS проверяются. Безусловное принятие недействительных сертификатов и обход проверки подписи исключены. Перенаправления не должны пересылать пароль на другой origin. Тестовый стенд явно доверяет своему сертификату, не использует production-обходов проверки.

## Демонстрация экрана

UI выбирает монитор или окно и запускает существующий `finch-screen`. Захват/кодирование выполняются вне UI и аудиоколбэков. H.264 IDR идёт uni-стримом QUIC, дельты — фрагментированными датаграммами; лимит IDR одинаков на сервере и клиенте (10 МиБ), конкурентные стримы ограничены. Просмотр использует бинарный Tauri Channel → WebCodecs → Canvas. Новый подписчик и потеря опорного кадра вызывают запрос IDR. Звук экрана передаётся и воспроизводится с отдельным декодером и уважает deafen. Остановка захвата, выход из комнаты, logout и обрыв соединения освобождают ресурсы.

## Подтверждение сообщений

Оптимистичное сообщение получает UUID запроса. Сервер возвращает его в успешном сообщении и относящейся к нему ошибке. Корреляция сохраняется в истории, чтобы восстановление после обрыва не создавало дубликат. Ошибка удаляет только относящийся к ней pending. Старые сообщения без корреляции остаются читаемыми. Чужие сообщения с одинаковым текстом не подтверждают локальную отправку.

## Критерии завершения

- Не снижаются исходные пороги: ERLE ≥20 дБ, потеря уровня речи при double-talk не более 6 дБ, обычная задержка ≤120 мс, плохая сеть ≤200 мс, jitter buffer ≤6 пакетов.
- `npm test`, `npm run build`, `cargo check --workspace --all-targets`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings` завершаются успешно.
- Игнорированные аудиорегрессии снимаются только после фактического прохождения. Ручные пункты голоса/захвата/устройств отмечаются исключительно по выполненной проверке; аппаратно недоступные пункты остаются явно открытыми.
- `HANDOFF`, отчёт аудита и `PROGRESS` отражают фактические результаты, а не планируемую готовность.
