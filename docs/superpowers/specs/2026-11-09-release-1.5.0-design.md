# FinchSpeak 1.5.0 — спецификация

Дата: 2026-11-10. Все решения ниже окончательные: часть принята владельцем в диалоге, остальное («на твой вкус») принято
автором спецификации и исполнителем не пересматривается. Если решение оказалось технически невыполнимым — исполнитель
останавливается, описывает причину и предлагает замену, а не выбирает молча.

Состояние репозитория, среда и порядок работы — в [HANDOFF-1.5.0.md](../HANDOFF-1.5.0.md).
Номера строк в ссылках соответствуют коммиту `5f44fe2` (релиз 1.4.1).

## 0. Общие правила для всех пакетов

- Один пункт — один коммит, тест первым (должен упасть до правки). Проверки перед каждым коммитом:
  `cargo check --workspace --all-targets`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`,
  в `app/frontend` — `npm test` и `npm run build`.
- Без `unwrap()/expect()/todo!()` в сетевом, серверном и аудио-коде (в тестах можно). `finch-server` не зависит от
  `finch-audio`, `finch-screen`, `finch-client-core`. В колбэках cpal нет мьютексов и аллокаций.
- Все строки интерфейса — через `t()` с русским переводом в `app/frontend/src/i18n/index.ts` ([I18N.md](../../I18N.md)).
  Ниже строки даны парой «English key» → «Русский текст»; использовать именно их.
- Стили — по [UI-STYLES.md](../../UI-STYLES.md): правило для одной темы всегда с префиксом `[data-theme="custom"]`, без `!important`,
  без инлайновых `style={{…}}` в новом коде. Анимируются только `transform` и `opacity`. Каждый новый элемент должен
  выглядеть корректно в темах `claude`, `custom` и `user`.
- Настройки, которые живут на этом компьютере, — в `settingsStore.ts` (`Prefs`, `parsePrefs`, `DEFAULT_PREFS`); каждое новое
  поле проходит через `parsePrefs` с починкой неверного значения и покрывается тестом в `settingsStore`-тестах.

### 0.1 Совместимость протокола

Управляющие сообщения кодируются `rmp_serde::to_vec_named` (map): новое поле с `#[serde(default)]` безопасно.
Новый **вариант** `ServerMessage` старый клиент разобрать не может. Поэтому:

- В `ClientMessage::Authenticate` добавить `#[serde(default)] client_level: u16`. Клиент 1.5.0 шлёт `150`.
  Старое поле `supports_voice_extensions` остаётся как есть.
- `ClientSession` на сервере хранит `client_level`. Сообщения, появившиеся в 1.5.0 (`ActivityChanged`, `MusicState`),
  сервер отправляет только сессиям с `client_level >= 150`. Сделать для этого один помощник в `SessionManager`
  (по образцу фильтра `requires_voice_extensions` в `session.rs:260`).
- Клиент 1.5.0 против сервера 1.4.x: REST-маршрутов музыки нет (404) — музыка и активность в интерфейсе скрываются.
  Признак: в `ServerState` добавляется `#[serde(default)] pub features: Vec<String>`; сервер 1.5.0 кладёт туда
  `"activity"` и, если `music.enabled`, `"music"`. У старых серверов список пуст. Фронтенд держит его в
  `sessionStore` (`serverFeatures()`), сбрасывает при отключении.

Причина: `crates/finch-server/src/api/state.rs` кладёт в `ServerState.online_users` только подключённых, клиент

- `state.rs`: один запрос по всем пользователям с `banned_at IS NULL`, `ORDER BY username`; подключённые → `online_users`
  (как сейчас), остальные → `offline_users` со `status: UserStatus::Offline`, `status_text: None`. Аватар и роль заполняются.
- Второе место создания `ServerState`: `crates/finch-client-core/tests/control_stream_test.rs:36`.
- Тест уже написан и лежит незакоммиченным: `state_lists_people_who_are_not_connected_as_offline`
  в `crates/finch-testbed/tests/state.rs`. Добавить второй: забаненный пользователь не попадает ни в один список.

Фронтенд:
- `types.ts`: `initial_state.offline_users?: User[]`.
- `sessionStore.ts`, обработчик `authenticated`: `knownUsers = [...online_users, ...(offline_users ?? [])]`;
  `presence` для офлайн — `'offline'`.
- `presence-update` для `user_id`, которого нет в `knownUsers` (зарегистрировался после моего подключения):
  вызвать `get_session_snapshot` и добавить в `knownUsers` только отсутствующих (остальные сторы не трогать).
  Одновременно не более одного запроса; повтор для того же id не чаще раза в 10 с.
- `MembersPanel.tsx` не меняется по логике; проверить, что строка офлайн-участника показывает аватар-картинку.
- Тесты: `sessionEvents.test.ts` — офлайн-список попадает в `knownUsers` со статусом offline; неизвестный id в
  `presence-update` вызывает дозагрузку ровно один раз. Тест панели: группа «Не в сети» содержит такого человека.

### 2.2 Анимация говорящего: пять вариантов

Настройка `prefs.appearance.speakingStyle: 'pulse' | 'ring' | 'waves' | 'bars' | 'glow'`, по умолчанию **`pulse`**.
`settingsStore` выставляет на `<html>` атрибут `data-speaking-style` (как `data-reduce-motion`).

Уровень громкости (нужен вариантам `pulse`, `bars`, `glow`):
- Rust, аудио-воркер (`app/src/audio_engine.rs`): событие `voice-levels` раз в 3 кадра (60 мс), только пока кто-то говорит;
  когда все замолчали — одно финальное событие с пустым списком. Полезная нагрузка: `{ "levels": [[peer_id, level], …] }`,
  `level` — целое 0..100.
- Расчёт: RMS декодированного 20-мс кадра участника в dBFS, `level = clamp((db + 50) / 40, 0, 1) * 100`, берётся максимум
  за три кадра. RMS по участнику считать в `finch-audio/src/mixer.rs` там, где кадр декодируется (без аллокаций),
  отдавать наружу методом вида `speaker_levels()`. Свой уровень — из обработанного кадра микрофона, только когда
  локальная речь активна и микрофон не выключен; `peer_id` — свой.
- Фронтенд: `stores/levelStore.ts` — не реактивный. `Map<peerId, Set<HTMLElement>>`; `bindLevel(el, peerId)` возвращает
  функцию отписки; на событие записывает `el.style.setProperty('--lvl', String(level / 100))`. Если по участнику нет
  обновления 200 мс — `--lvl` = 0. Сигналы Solid для уровня не используются (иначе перерисовка 16 раз в секунду).
- `Avatar.tsx`: новый проп `levelPeerId?: number`; при наличии вызывает `bindLevel` на корневом `span.av` в `onMount`,
  отписка в `onCleanup`. Передавать его из `ParticipantTile`, строк `.vp` в `Sidebar`, ростера в `VoicePanel` и своей
  панели внизу слева.

Варианты (все — в `motion.css`, селектор `[data-speaking-style="…"] .av.speaking …`):

| Значение | Название | Поведение |
| --- | --- | --- |
| `pulse` (умолчание) | Pulse → «Пульс» | Слой `.av-speaking-ring`: `transform: scale(calc(1 + var(--lvl, 0) * .14))`, `opacity: calc(.55 + var(--lvl, 0) * .45)`; `transition: transform 90ms linear, opacity 90ms linear`. |
| `ring` | Ring → «Кольцо» | Текущее поведение 1.4.1 без изменений: статичное кольцо, плавно появляется. |
| `waves` | Waves → «Волны» | Два кольца (`::before` и `::after` у `.av-speaking-ring`) расходятся: `scale(1) → scale(1.45)`, `opacity .6 → 0`, 1.4 с, `ease-out`, бесконечно, второе с задержкой 0.7 с. От уровня не зависит. Идёт только при `.speaking`. |
| `bars` | Equalizer → «Эквалайзер» | Новый элемент `span.av-bars` с четырьмя `<i>` по центру нижнего края аватара. Высота: `transform: scaleY(calc(.25 + var(--lvl, 0) * k))`, `k` = 0.6, 1, 0.8, 0.5; `transform-origin: bottom`; длительности перехода 70, 110, 90, 130 мс. Виден только при `.speaking`. Для аватаров меньше 40 px вместо него работает `pulse`. Кольцо остаётся статичным. |
| `glow` | Glow → «Свечение» | Слой-ореол за аватаром (статичный `box-shadow` на отдельном слое): `opacity: calc(.25 + var(--lvl, 0) * .75)`, `transform: scale(calc(1 + var(--lvl, 0) * .25))`, переход 120 мс. |

- Цвет везде — существующая `var(--cyan)` / `var(--glow-speak)`; новых цветов не вводить.
- `data-reduce-motion="true"` и `prefers-reduced-motion: reduce` принудительно дают поведение `ring` без перехода.
- Рамка плитки `.vc.speaking` не меняется ни в одном варианте.
- Настройки (`SettingsModal.tsx`, раздел внешнего вида): строка «Speaking animation» → «Анимация речи», пять кнопок-сегментов
  с названиями из таблицы и подписью «How your avatar and others' react to voice.» → «Как аватары реагируют на голос.».
  Рядом — аватар пользователя размером 56 с классом `speaking`, на котором выбранный вариант показывается на синтетическом
  уровне (таймер 80 мс, синус 0.2–1; только пока раздел открыт; при reduce motion таймер не запускается).
- Тесты: `parsePrefs` чинит неизвестное значение на `pulse`; атрибут на `<html>` следует настройке; `levelStore` пишет `--lvl`
  и обнуляет через 200 мс; CSS-тест (`styles/cssTest.ts`) проверяет наличие правил для всех пяти значений и правило reduce motion.
- Обновить [UI-MOTION-2026-11.md](../../UI-MOTION-2026-11.md): циклические анимации теперь допущены только для индикатора речи.

## Пакет 3. Стрим: захват, стабильность, 60 FPS

Жалобы владельца: FPS проседает; свёрнутое окно (игра после Alt+Tab) нельзя выбрать; полноэкранная игра не видна.

### 3.0 Сначала замер

До правок добавить статистику и записать базовые цифры в `docs/QA-1.5.0.md` (стрим монитора 1920×1080, 60 с, на этой машине):
- В `ScreenSharer` (`crates/finch-client-core/src/screen.rs`) считать: кадров захвачено/с, закодировано/с, среднее и
  максимальное время конвертации и кодирования, число `Dropped`, текущий битрейт.
- Раз в 2 с отдавать наружу через колбэк; `app` шлёт событие `screen-share-stats`
  `{ captured_fps, sent_fps, encode_ms, bitrate_kbps }`. Раз в 10 с — строка `tracing::info!`.
- `SharerPill.tsx` показывает «{fps} FPS · {bitrate}» (через `unit('fps')` и `formatBitrate`).

### 3.1 Захват через Windows Graphics Capture

- В `finch-screen` добавить модуль `wgc.rs` (`#[cfg(windows)]`) на крейте **`windows-capture`** (последняя 1.x).
  Если его API не позволяет нужного ниже — реализовать то же напрямую на крейте `windows`
  (`Direct3D11CaptureFramePool`), не меняя внешний интерфейс модуля.
- Интерфейс: поток-источник, который держит сессию захвата монитора или окна и кладёт в общий слот **последний** кадр
  (BGRA, без лишних копий: один `memcpy` из текстуры в переиспользуемый буфер). Рамку захвата отключать, где система
  позволяет (`IsBorderRequired = false`), курсор захватывать.
- `FrameSource` в `screen.rs` получает реализацию `WgcSource`. Выбор источника в `app/src/commands/screen.rs`:
  на Windows сначала WGC; если сессия не создалась (старая Windows, отказ) — прежние `MonitorSource`/`WindowSource`
  на `xcap` и предупреждение в лог. Миниатюры в окне выбора остаются на `xcap`.
- Статичный экран: WGC не присылает кадры без изменений. Кодирующий поток хранит последний кадр и повторно кодирует его,
  если нового нет: (а) по запросу ключевого кадра, (б) не реже раза в секунду. Иначе новый зритель не получит картинку.
- Лишние копии убрать: `fit_to_bgra` (`screen.rs:255`) при совпадении формата и размера не копирует кадр (`Cow`/срез).
- Ритм кодирующего потока — по абсолютным дедлайнам (`next += interval`), а не `sleep(interval − elapsed)` с
  целочисленными миллисекундами.

### 3.2 Свёрнутые окна и полноэкранные игры

- `list_screen_sources` (`app/src/commands/screen.rs`): убрать фильтр `!w.is_minimized`; в `WindowDto` добавить
  `is_minimized: bool`. Окна нулевого размера и без заголовка по-прежнему отбрасываются, кроме свёрнутых (у них размер
  может быть нулевым).
- Окно выбора: у свёрнутого окна вместо миниатюры — заглушка с иконкой и меткой «Minimized» → «Свёрнуто»; под сеткой
  подсказка «A minimized window shows up for viewers once you open it.» → «Свёрнутое окно появится у зрителей, когда вы его
  развернёте.». Текст пустого списка заменить на «Open the window you want and refresh.» → «Откройте нужное окно и обновите
  список.».
- Старт стрима свёрнутого окна: первый кадр получить нельзя, размер для `StartScreenShare` брать из
  `GetWindowPlacement().rcNormalPosition`, при неудаче — размер основного монитора. Стрим стартует без ошибки.
- Пока окно свёрнуто (`IsIconic`) или кадров нет, а окно существует, — это **не** сбой: счётчик `MAX_CAPTURE_FAILURES`
  не растёт, стрим ждёт сколько угодно. Окно закрыто — стрим завершается с причиной, как сейчас. При появлении первого
  кадра после паузы — принудительный ключевой кадр.
- У зрителя во время такой паузы показывается существующее состояние ожидания; текст для этого случая:
  «{name} minimized the shared window.» → «{name} свернул(а) окно, которое показывает.». Признак паузы стример шлёт
  существующим механизмом состояния (если подходящего нет — зритель показывает обычное «Waiting for the first picture…»,
  новое сообщение протокола ради этого не вводить).
- Полноэкранная игра: проверка — стрим **монитора**, на котором запущена игра в полноэкранном режиме, показывает игру
  зрителю; стрим **окна** игры показывает игру, пока оно на экране. Проверять на реальной игре с диска E (Steam).
  Если конкретная игра в эксклюзивном полноэкранном режиме через WGC не захватывается — зафиксировать в `QA-1.5.0.md`
  название и режим; DXGI Desktop Duplication в этом релизе не добавлять.

### 3.3 Передача кадров зрителю без JSON

- Сейчас `VideoChunkPayload { is_key, data: Vec<u8> }` сериализуется в JSON-массив чисел (`ViewerPanel.tsx:11-14`).
- Заменить на сырые байты: канал `tauri::ipc::Channel` отправляет `InvokeResponseBody::Raw`; первый байт — флаги
  (бит 0 = ключевой кадр), дальше H.264. Во фронтенде `onmessage` получает `ArrayBuffer`.
- Метка времени чанка — реальное время в микросекундах (`performance.now() * 1000`), а не шаг `33333`.
- `captureStream(30)` для «картинки в картинке» — с частотой из `ScreenShareStarted.fps`.
- Тесты `screenUi.test.tsx`/`screenStore.test.ts` обновить под новый формат.

### 3.4 Режим 60 FPS

- `start_screen_share` получает параметр `fps: Option<u8>`; допустимы только 30 и 60 (иное → 30). Константа `SHARE_FPS` уходит.
- Окно выбора: сегмент «Frame rate» → «Частота кадров» с кнопками «30» и «60». Подпись под 60:
  «Smoother, but needs a faster computer and connection. The picture is limited to 1080p.» →
  «Плавнее, но требует более мощного компьютера и канала. Картинка ограничена 1080p.».
  Выбор хранится в `localStorage` (`finchspeak.shareFps`), по умолчанию 30. Старую подпись «30 frames per second; …»
  заменить на «Pictures larger than 4K are scaled down before they are sent.» → «Изображения больше 4K уменьшаются перед отправкой.».
- В режиме 60 картинка вписывается в 1920×1080 с сохранением пропорций (`encoded_size` получает предел как параметр);
  в режиме 30 предел прежний.
- Битрейт (`default_bitrate`): 30 FPS — как сейчас (`w·h·fps/12`, 1–8 Мбит/с); 60 FPS — `w·h·60/18`, 1–10 Мбит/с
  (1080p60 ≈ 6.9 Мбит/с). Юнит-тесты на оба случая.
- Автооткат: если в режиме 60 среднее время кодирования кадра за 3 с подряд больше 15 мс, стример переходит на 30 FPS
  до конца стрима, пересоздаёт кодер и шлёт событие `screen-share-fps-fallback`; фронтенд показывает тост
  «Switched to 30 FPS» → «Переключено на 30 FPS» /

### 6.1 Определение (клиент, `app/src/activity.rs`)

## Пакет 7. Музыкальный плеер комнаты

### 7.1 Архитектура (решение)

Музыка **не** идёт живым аудиопотоком от участника. Каждый трек — файл на сервере; клиенты скачивают его и играют сами,
синхронно по состоянию, которое ведёт сервер.

- «Со своего компьютера для всех» = временная загрузка: файл заливается на сервер как временный трек, ставится в очередь и
  удаляется, когда покидает очередь.
- «Залить на сервер» = тот же путь, но трек остаётся в общей библиотеке.

Почему так: стереозвук без пережатия в Opus; музыка не обрывается, когда ведущий вышел; не трогается голосовой тракт
(микшер сейчас декодирует звук стрима в моно); один механизм на оба источника.

Воспроизведение — в Rust-аудиодвижке, а не в `<audio>` WebView: только так музыка идёт на выбранное в FinchSpeak
устройство вывода и попадает в опорный сигнал эхоподавления (иначе музыка из колонок уходит в микрофон).

### 7.2 Сервер

Конфиг (`config.rs`, новая секция `[music]`, все поля с умолчаниями):
`enabled = true`, `max_track_mb = 30`, `library_quota_mb = 2048`, `temp_quota_mb_per_user = 200`, `max_queue = 100`,
`max_track_minutes = 180`. Каталог — `{storage.upload_dir}/music`.

Миграция `012_music.sql`: таблица `music_tracks` (`id TEXT PRIMARY KEY`, `uploader_id TEXT NOT NULL`, `title TEXT NOT NULL`,
`artist TEXT`, `duration_ms INTEGER NOT NULL`, `size_bytes INTEGER NOT NULL`, `format TEXT NOT NULL`, `path TEXT NOT NULL`,
`temporary INTEGER NOT NULL`, `created_at INTEGER NOT NULL`).

REST (новый модуль `api/music.rs`, все маршруты требуют авторизации):
- `POST /api/music/tracks` — multipart: `file`, `title`, `artist` (может быть пустым), `duration_ms`, `keep` (`true`/`false`).
  Проверки: `music.enabled`; размер ≤ `max_track_mb`; формат по сигнатуре файла, а не по имени — MP3 (`ID3` или
  синхрослово кадра MPEG), Ogg (`OggS`), FLAC (`fLaC`), WAV (`RIFF…WAVE`); `duration_ms` в пределах 1 с … `max_track_minutes`;
  `title` 1–120 символов, `artist` ≤ 120; для `keep=true` — суммарный размер библиотеки ≤ `library_quota_mb`;
  для `keep=false` — суммарный размер временных треков пользователя ≤ `temp_quota_mb_per_user`.
  Ограничение частоты: 10 загрузок в минуту на пользователя. Ответ — `MusicTrack`.
- `GET /api/music/tracks` — библиотека (`temporary = 0`), по убыванию `created_at`.
- `GET /api/music/tracks/{id}/file` — байты с корректным `Content-Type`.
- `DELETE /api/music/tracks/{id}` — автор трека или персонал. Трек, стоящий в чьей-то очереди, из очереди убирается.
- `ServerState.features` включает `music`, если `music.enabled` (см. 0.1).

Длительность и теги сервер сам не разбирает (у него нет аудио-зависимостей): их присылает клиент; сервер доверяет в
указанных границах.

Состояние комнаты (в памяти, в `VoiceRoom`): `MusicRoomState { queue: Vec<QueueEntry>, playing: Option<Playing> }`.
- `QueueEntry { entry_id: Uuid, track: MusicTrack, added_by: Uuid }`.
- `Playing { entry: QueueEntry, position_ms: u64, at_server_ms: u64, paused: bool }` — позиция на момент `at_server_ms`.
- Таймер конца трека — задача tokio на комнату; пересоздаётся при каждом изменении; по срабатыванию запускает следующий
  трек из очереди или останавливает музыку.
- Комната опустела → музыка останавливается, очередь очищается, временные треки удаляются.
- Временный трек удаляется (файл и строка), когда покидает очередь любым способом. При старте сервера все временные
  треки удаляются.

Управляющие сообщения:
- `ClientMessage::MusicCommand { command: MusicCommand }`, где `MusicCommand` (serde-тег `kind`):
  `Enqueue { track_id }`, `Pause`, `Resume`, `Skip`, `Seek { position_ms }`, `Remove { entry_id }`, `Clear`.
  Действует на комнату, в которой сейчас находится отправитель; вне комнаты — `Error`.
- Права: `Enqueue`, `Pause`, `Resume`, `Skip`, `Seek` — любой участник комнаты. `Remove` — тот, кто добавил, или персонал.
  `Clear` (остановить и очистить всё) — только персонал. `server_muted` участник управлять музыкой не может.
- Ограничение частоты: 20 команд за 10 с на сессию.
- `ServerMessage::MusicState { channel_id, state: MusicRoomState, server_ms }` — участникам комнаты с
  `client_level >= 150` при каждом изменении и входящему при `JoinVoice`. Пустое состояние (`playing: None`, пустая
  очередь) тоже рассылается.
- Тесты testbed: загрузка и отказ по каждому ограничению; очередь и права; автопереход по таймеру (трек 1 с);
  пауза/продолжение сохраняют позицию; вошедший получает состояние; опустевшая комната очищается и удаляет временные
  файлы; старый клиент сообщений не получает.

### 7.3 Клиент: декодирование и воспроизведение

- `finch-audio`: модуль `music.rs` на крейте **`symphonia`** (возможности: `mp3`, `flac`, `vorbis`, `wav`, `ogg`).
  - `probe(bytes) -> TrackInfo { duration_ms, title, artist }` — для загрузки (теги; при отсутствии заголовка — имя файла
    без расширения, это подставляет вызывающий).
  - `MusicDecoder::open(path, start_ms)` → поток стерео-кадров 48 кГц `f32` (ресемплинг существующим `rubato`,
    моно дублируется в оба канала).
- `app/src/music.rs`: `MusicPlayer`.
  - Кэш файлов: `{app_cache_dir}/music/{track_id}.{ext}`, предел 500 МБ, вытеснение по давности использования.
    Скачивание через `ApiClient` с проверкой размера.
  - Поток декодирования пишет в lock-free `ringbuf` (стерео, ~1 с); аудио-воркер (не колбэк cpal) на каждом 20-мс кадре
    забирает 960 стерео-сэмплов и подмешивает в левый/правый каналы воспроизведения с усилением громкости музыки.
    Подмешивание — **до** точки, где берётся опорный сигнал AEC (вместе с удалёнными голосами и звуком стрима).
    При deafen музыка тоже молчит.
  - Синхронизация: смещение часов `offset = server_ms − (local_now − rtt/2)` на момент получения `MusicState`
    (`rtt` — из существующего ping). Целевая позиция `position_ms + (now_server − at_server_ms)`. При получении
    состояния: расхождение с текущей позицией > 250 мс — перезапуск декодера с целевой позиции; меньше — ничего.
    Пауза — остановка подмешивания с сохранением позиции.
  - Трек ещё качается — играть с позиции, актуальной на момент готовности.
  - Ошибка скачивания или декодирования — событие `music-error` и тост, музыка у остальных не затрагивается.
- Команды Tauri: `music_library`, `music_upload` (сырые байты в теле запроса, имя файла и `keep` — в заголовках
  `invoke`; **не** `number[]`), `music_delete_track`, `music_command`, `music_set_volume`. Событие `music-state` — проброс
  `MusicState` во фронтенд.
- Громкость музыки — личная: 0–100 %, по умолчанию 50 %, ключ `music` в `volumeStore`; кнопка «выключить музыку у себя» = 0
  с запоминанием прежнего значения.
- Стрим со звуком: при захвате «всё, кроме FinchSpeak» музыка зрителям не дублируется. При откате на захват устройства
  дублируется — известное ограничение, записать в `QA-1.5.0.md`.

### 7.4 Интерфейс

- Кнопка в доке (`voice/Dock.tsx`) между «стрим» и «настройки»: значок `music` (добавить), подпись «Music» → «Музыка»;
  подсвечена, пока что-то играет. Открывает панель справа в области комнаты (`VoicePanel`), ширина 340 px; при окне уже
  940 px — модальное окно.
- Панель `components/music/MusicPanel.tsx`:
  - «Сейчас играет»: название, исполнитель, кто добавил, полоса прогресса с перемоткой (ползунок `Slider`), время
    `formatDuration`, кнопки пауза/продолжить и «следующий», ползунок личной громкости, кнопка «Stop for everyone» →
    «Остановить у всех» (только персонал).
  - Очередь: список (название, длительность, кто добавил, кнопка удаления по правам). Пусто —
    «Nothing is playing. Add a track to start.» → «Ничего не играет. Добавьте трек, чтобы начать.».
  - «Добавить»: две вкладки.
    - «Library» → «Библиотека»: поиск по названию/исполнителю (на клиенте), строка трека → «в очередь»; кнопка
      «Upload to the server» → «Загрузить на сервер»; у своих треков (и у всех — персоналу) кнопка удаления с подтверждением
      `ConfirmDialog`.
    - «From my computer» → «С моего компьютера»: выбор файлов (`input type=file`, `accept` — mp3/ogg/flac/wav, несколько),
      подпись «The file is sent to the server for this session and removed after it plays.» →
      «Файл отправляется на сервер на время прослушивания и удаляется после проигрывания.»; после загрузки трек сразу в очереди.
  - Прогресс загрузки по каждому файлу; ошибки сервера — понятным текстом через `i18n/errors.ts`
    (слишком большой, неподдерживаемый формат, квота исчерпана, очередь полна).
- Строка «сейчас играет» в шапке комнаты (`.mhead`): значок, название, бегущая позиция; клик открывает панель.
- В полосе голосового подключения в `Sidebar` (`.vstrip`): значок ноты, если в комнате играет музыка.
- Если сервер не объявил `music` — кнопки и панели нет.
- Стор `stores/musicStore.ts`; локальная позиция тикает раз в 500 мс от состояния сервера (без запросов).
- Тесты: стор (состояние → позиция, пауза), панель (права на кнопки по ролям, пустое состояние, ошибки загрузки),
  локализация.
