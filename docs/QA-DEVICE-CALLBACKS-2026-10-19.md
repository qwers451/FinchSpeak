# Локальное прерывистое воспроизведение на другом ПК

Сообщение пользователя: Windows 11, прерывистый роботизированный звук в «Проверить микрофон» и «Слышать себя»; проблема остаётся на звуке ноутбука, а Диктофон Windows и Discord работают нормально. Это не подтверждает первоначальную гипотезу о Bluetooth. Параметры callback проблемного устройства пока не получены; исправленная сборка на том ПК не проверялась.

## Воспроизведённый дефект

Очередь выхода поддерживала только 60 мс звука, независимо от размера запроса устройства. В регрессионном стенде callback запрашивает 100 мс непрерывного сигнала, получает 60 мс и затем пустую очередь. Production callback заменяет пустую очередь нулями. Старый код падает на этом условии (`target/audio-network-qa/device-callback-red.log`). Это подтверждённый дефект, но его совпадение с причиной пользовательского случая ещё требует проверки на ноутбуке.

## Изменение

Callback сообщает максимальное наблюдавшееся число mono frames через atomic; выделений памяти и блокировок в callback не добавлено. Worker поддерживает очередь не меньше одного callback плюс 20 мс, сохраняя прежнюю цель 60 мс для небольших callback. Цель ограничена размером ring buffer с местом для очередного полного кадра. Конфигурации входа и выхода (имя, частота, каналы, формат) добавлены в tracing.

Регрессия проверяет пять последовательных запросов по 10 и 100 мс на 8 / 16 / 44,1 / 48 / 96 кГц: каждый отсчёт сигнала должен дойти без вставки тишины. Отдельно проверены прежняя цель для малого callback и ограничение арифметики для чрезмерного запроса.

Независимое ревью не нашло блокирующих проблем в покрытом диапазоне. Ограничения: один необычно большой callback увеличивает цель до конца сессии; запрос больше ёмкости ring buffer не может обслуживаться целиком. При 192 кГц запрос 100 мс превышает текущую ёмкость 16384 mono samples. Начальный callback, пока worker ещё не узнал его размер, также может получить стартовую тишину. Изменение не обещает устранить все прерывания или восстановить качество Bluetooth HFP.

Это исправление сделано после стабильной 1.2.2 и не входит в её установщик.

Проверки окончательного кода: весь `finch-app` — 49 PASS (46 unit + 3 integration), два явно помеченных теста живого микрофона пропущены; Clippy `--all-targets --locked --offline -- -D warnings` — PASS. Логи: `device-callback-app-final.log`, `device-callback-clippy.log` в `target/audio-network-qa`. Физический ноутбук пользователя и его гарнитура в автоматический стенд не входят.
