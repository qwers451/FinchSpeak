### 7.1 Каркас (≈2 дня)
- Макет C1/B2: боковая панель 264 px (бренд, каналы, голосовые с участниками, полоса «голос подключён», панель пользователя), панель участников 240 px со сворачиванием, шапка канала.
- Адаптация: при ширине < 1000 px боковая панель сворачивается в иконки (разворачивается поверх), участники скрыты по умолчанию; минимальное окно 900×600.
- Состояния каналов (по дизайну B2): наведение, активный, непрочитанный (жирный + счётчик, 99+), упоминание (красный счётчик), заглушён, длинные имена, сворачиваемые категории. Действия админа при наведении уже есть.
- Тесты: рендер состояний; клавиатурная навигация по списку каналов; визуальная сверка (7.9).

### 7.2 Вход и доверие (≈2 дня)
- A1/A2: форма входа и регистрации по дизайну; ошибки человеческими фразами (неверный пароль, забанен, сервер недоступен, код приглашения, имя занято); индикатор надёжности пароля.
- A3: отпечаток сгруппированными байтами, без кнопки по умолчанию.
- A4: «сертификат изменился» с двумя отпечатками и подсветкой отличий, ввод имени сервера для продолжения. **Бэкенд:** команда `forget_server_fingerprint(hostname)` в Tauri, сейчас такого пути нет. Тест: после «Отключиться» отпечаток не меняется; после ввода имени и подтверждения старый удаляется и показывается обычный диалог A3.
- A5: заставка с волнами, баннеры «переподключение / связь потеряна / не удалось», повторы с обратным отсчётом (событие `reconnecting` дополнить номером попытки и временем до следующей).

### 7.3 Чат (≈4–5 дней; бэкенд из части B4 раньше)
- Группировка сообщений одного автора, разделитель дней, разделитель «Новые сообщения» (по серверному маркеру прочитанного, B4.1), «(edited)», подсветка упоминаний, свои сообщения.
- Панель действий при наведении (реакция, копировать, правка, удаление), палитра эмодзи (быстрый ряд + сетка + поиск), чипы реакций с подсказкой «кто поставил».
- Правка на месте, подтверждение удаления с цитатой сообщения.
- Вложения: перетаскивание файла в окно и кнопка, прогресс загрузки (Tauri-события `upload-progress`), ошибка лимита (10 MB), «не удалось — повторить», превью картинок (миниатюра с сервера, B4.4), открытие просмотрщика.
- Композитор: автодополнение `@` (список участников), счётчик символов над 4000, состояние «нет связи», строка «печатает».
- Состояния: скелетон истории, пустой канал, «не отправлено — повторить / удалить», тост отказа.
- Шапка канала: тема (правка админом), число участников, поиск (B4.5).
- Тесты: сторы (уже есть для основной логики) + DOM-тесты каждого состояния; живой прогон двумя клиентами.

### 7.4 Голос (≈3–4 дня; часть B2)
- Карточки участников D1/D2: аватар, кольцо речи (пульс), значки mute/deafen/эфир, индикатор качества, ползунок громкости 0–200 % (сохраняется), раскладки 1/2/4/8/12+ с закреплением говорящих и ростером при тесноте.
- Панель управления: mute, deafen, эфир, настройки, выход, «● talking» для PTT.
- Настройки голоса D3: **живой индикатор уровня** (событие `mic-level` ~20 раз/с из аудиопотока, без блокировок в колбэке), маркер порога на шкале, «Проверить микрофон» (запись 3 с и проигрывание), баннеры «гарнитура отключена», запись клавиши с конфликтом.
- Тесты: чистая логика раскладки (сколько колонок, какие плитки видны), хранилище громкостей, события уровня. Живой: слышно/видно изменения вручную (чек-лист).

### 7.5 Показ экрана (≈4–5 дней; бэкенд раньше)
- **Живые превью** в выборе: команда `capture_thumbnail(kind,id,max_width)` → JPEG ≈320 px, обновление раз в секунду, без нагрузки на кодировщик; кэш; «окна свёрнутые не показываем».
- Полоса «Вы в эфире» (E2): плавающая плашка; решение: отдельное маленькое окно поверх всех (видно, даже когда вы в игре) — нужно разрешение окна `always_on_top` и положение по умолчанию; запасной вариант — плашка внутри главного окна.
- Зритель E3/E4: HUD (имя, разрешение, FPS, битрейт, качество), громкость звука эфира (есть), PiP (Picture-in-Picture API webview, если недоступен — скрыть кнопку), полный экран (Tauri `set_fullscreen`), автоскрытие HUD через 3 с. События состояний от бэкенда: `waiting-key`, `buffering`, `quality-lowered`, `decoder-reset`, `ended{reason: sharer-stopped | sharer-left | connection}`, `unsupported`.
- Проверка поддержки H.264 заранее (`VideoDecoder.isConfigSupported`) и понятное сообщение (E4/6).
- Несколько эфиров в комнате: карточки LIVE, один просматриваемый.
- Тесты: сборка событий состояний в `ScreenViewer` (юнит), превью (юнит: размер, формат), UI-состояния; живой прогон показа с двумя клиентами (как делал раньше).

### 7.6 Профиль, аватары, настройки (≈3 дня; бэкенд B3)
- F1/F2: профиль с аватаром (загрузка, кроп в круг, удаление, ошибки размера/формата, прогресс), имя, статус (онлайн/не на месте/не беспокоить/невидимка) и своя строка статуса, смена пароля с индикатором надёжности.
- F3: уведомления (упоминания, все сообщения, вход в голос, звуки, громкость звуков, мигание панели задач), заглушённые каналы со сроком, «не беспокоить»; внешний вид (интенсивность акцента, плотность, размер текста, уменьшение анимации, панель участников).
- F4: горячие клавиши (запись, конфликт, сброс), «О программе» (версия, адрес, отпечаток с копированием, «Скопировать диагностику», открыть папку логов).
- Аватары в чате, списке участников, голосовых карточках, подсказках, «печатает»; генерируемый цвет по id; «+N» в стопке.
- Тесты: сторы настроек (сохранение/чтение, повреждённые данные), логика цвета по id, DOM.

### 7.7 Администрирование (≈3 дня; бэкенд B5/B6)
- H1: таблица с последним визитом, фильтр, подтверждения (диалоги с последствиями), защитные сообщения.
- H2: поле «число использований», срок, крупный новый код с копированием, статусы «использован/истёк».
- H3: перетаскивание каналов (pointer events + клавиатурная альтернатива ↑↓), правка на месте, создание с битрейтом, удаление с описанием последствий.
- H4: «Сервер» — **нужен эндпоинт** `GET /api/admin/server` (версия, аптайм, отпечаток, время и размер последнего бэкапа, число копий, использование места под загрузки, порты, режим регистрации) и `PUT /api/admin/registration` (хранится в таблице `settings`, а не в TOML, чтобы переключать без перезапуска), «Сделать бэкап сейчас».
- Журнал действий (B5.4) как пятая вкладка.

### 7.8 Обратная связь и системные экраны (≈2–3 дня)
- Уведомления ОС (плагин `tauri-plugin-notification`): упоминания, вход в голос; тот же текст, что в приложении; нажатие открывает канал.
- Звуки (короткие «чирики» для упоминания и входа): **нужны файлы звуков** (я сгенерирую простые тона из кода, чтобы не скачивать).
- Иконка в трее с состояниями (в голосе / mute / говорю / упоминания) через `tray-icon` Tauri, меню трея; поведение закрытия окна («свернуть в трей», настраиваемо).
- Оверлей горячих клавиш (`?`), быстрый переключатель (Ctrl+K).
- Экраны завершения сессии I2: выход из-за смены пароля, кик, бан, офлайн (бэкенд закрывает соединение с причиной; клиент различает причины: добавить код причины в закрытие QUIC и в 401/403 REST).
- Установщик: оформление NSIS (иллюстрация, цвета) — вместе с B6.2.

### 7.9 Сверка с дизайном и доступность (≈2 дня, идёт параллельно)
- Скрипт на базе моих CDP-скриптов: открывает приложение в каждом состоянии, снимает скриншоты, сравнивает с эталонами (допуск по пикселям), хранит в `docs/design-baseline/`. Эталонные картинки получаем экспортом артбордов; если экспорт недоступен, эталон — первый принятый вами вариант.
- Проверки доступности: контраст (скрипт по токенам), фокус-порядок, `aria-label` у иконок, цели ≥ 44 px, `prefers-reduced-motion`.
- Минимальный размер 900×600: сверка двух макетов.
- Ручной чек-лист: новый раздел 8 `manual-voice-checklist.md` по каждому экрану.

Для каждой задачи: тест до кода (RED), реализация (GREEN), полный `cargo test --workspace`, `clippy -D warnings`, `npm test`, `npm run build`, живой прогон в двух клиентах через WebView2 (мой скрипт), запись в `BASELINE.md`, если меняются метрики, обновление [чек-листа](audit/manual-voice-checklist.md). ## Решения владельца

Все вопросы ниже закрыты, ответы в [DECISIONS-STAGE-7.md](DECISIONS-STAGE-7.md) (они главнее этого текста там, где отличаются). Исходный список оставлен для истории.

### Исходный список вопросов

1. **Скачивание файлов.** Шрифты Nunito/Inter (woff2, лицензия OFL) и NSIS для установщика: разрешаете скачать? Шрифты без этого пришлось бы заменить системными.
2. **Плашка «вы в эфире»:** отдельное окно поверх всех (рекомендую) или внутри главного окна?
3. **Роль модератора** нужна? (по умолчанию: да, права в B5.1).
4. **Превью ссылок:** сервер ходит по ссылкам из чата (приватность и риск SSRF) — рекомендую **не делать**; вариант: превью только для прямых ссылок на картинки, загрузка клиентом.
5. **Запоминание пароля** в хранилище Windows (Credential Manager): да или только адрес и логин?
6. **Автообновление:** где публикуем релизы (репозиторий GitHub) и кто хранит ключ подписи?
7. **Подпись кода:** покупать сертификат или жить с предупреждением SmartScreen?
8. **Звуки:** простые синтезированные тона подойдут, или есть свои файлы?
9. **Закрытие окна:** сворачивать в трей (рекомендую для голоса) или выходить?
10. **Экспорт эталонов дизайна** для сверки скриншотов: сделаете экспорт PNG артбордов, или эталоном считается первый принятый вами вариант?
