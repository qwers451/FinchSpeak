# Локализация интерфейса

Интерфейс FinchSpeak работает на русском и английском. Всё, что относится к переводу, лежит в `app/frontend/src/i18n/index.ts`. Английский текст — исходный: он же служит ключом в русском словаре. Язык выбирается в «Профиль и настройки → Внешний вид».

Не переводятся тексты, которые ввели люди или прислал сервер: имена, сообщения, названия каналов, тексты статусов.

## Что есть в `i18n/index.ts`

| Что | Для чего |
| --- | --- |
| `ru` | Русский словарь: `'English text': 'Русский текст'`. |
| `t(source, params?)` | Перевод строки; `{имя}` в тексте заменяется значением из `params`, числа форматируются по языку интерфейса. |
| `plural(count, { one, other }, params?)` | Фраза с числом в нужной форме множественного числа. |
| `ruPlurals` | Русские формы для `plural()`: `one`, `few`, `many`, `other`. |
| `formatNumber`, `formatBytes`, `formatBitrate`, `formatDuration`, `unit` | Числа, размеры, битрейт, длительности и подписи единиц на языке интерфейса. |
| `locale()` | Текущий язык, реактивный. |

## Как добавить строку

1. В компоненте напишите английский текст через `t()`: `t('Ban {name}', { name })`.
2. Добавьте русский текст в `ru` с тем же ключом и теми же `{подстановками}`: `'Ban {name}': 'Заблокировать {name}'`.
3. Запустите тесты (см. ниже): тест полноты скажет, если ключ или подстановка пропущены.

Правила:

- Через `t()` проходят и видимый текст, и `aria-label`, `title`, `placeholder`, `alt`, и тексты уведомлений.
- Не склеивайте фразу из кусков: порядок слов в русском другой. Пишите одну строку с подстановками: `t('{name} left the room', { name })`.
- Если текст выбирается по условию, оба варианта должны быть явными строками: `t(muted ? 'Unmute' : 'Mute')`. Подпись, собранная из переменных, тест не увидит.
- Одно и то же английское слово в разных значениях — разные ключи, если по-русски они различаются («good» для связи — «хорошее», «Good» для надёжности пароля — «Хороший»).
- Ключ — точный английский текст, включая пробелы и знаки. Изменили английский текст — измените ключ в словаре.
- Не вставляйте в перевод `{…}`, которых нет в ключе, и не теряйте те, что есть: тест сравнивает наборы.

## Формы множественного числа

В русском три формы (и ещё одна для дробных чисел), в английском две. Для фраз «число + существительное» используйте `plural()`, а не `t()` с условием:

```ts
plural(count, { one: '{count} new message', other: '{count} new messages' })
```

Английские формы передаются в вызове. Русские лежат в `ruPlurals` под ключом — английской формой `other`:

```ts
'{count} new messages': {
  one: '{count} новое сообщение',     // 1, 21, 31 …
  few: '{count} новых сообщения',     // 2–4, 22–24 …
  many: '{count} новых сообщений',    // 0, 5–20, 25–30, 111 …
  other: '{count} новых сообщения',   // дробные числа
}
```

Форму выбирает `Intl.PluralRules`, поэтому «21 новое сообщение», «22 новых сообщения», «25 новых сообщений», «111 новых сообщений» получаются сами. Если для фразы нет записи в `ruPlurals`, русский интерфейс покажет английскую форму `other`; тест полноты не даст оставить так фразу, добавленную в код.

## Единицы и длительности

Размеры, битрейт и время не пишите руками вроде `` `${n} MB` ``. Используйте форматтеры:

| Функция | Результат ru / en |
| --- | --- |
| `formatBytes(n)` | `500 Б` / `500 B`, `2 КБ` / `2 KB`, `5,5 МБ` / `5.5 MB`, `3 ГБ` / `3 GB` |
| `formatBytes(n, 'KB')` | то же, но всё меньше мегабайта показывается в килобайтах (не менее 1 КБ) |
| `formatBitrate(kbps)` | `850 кбит/с` / `850 kbps`, `2,5 Мбит/с` / `2.5 Mbps` |
| `formatDuration(seconds)` | `5 мин`, `2 ч`, `1 д 2 ч` / `5 min`, `2 h`, `1 d 2 h` |
| `unit('fps')` | `кадр/с` / `fps` |

Новая единица добавляется в обе таблицы `UNITS`. Английский вид существующих значений не менялся.

## Что проверяет тест и как его запускать

Тест `app/frontend/src/i18n/coverage.test.ts` читает исходники как текст и ловит то, что не видно при обычном запуске интерфейса: пропуски в местах, куда редко заходят.

| Проверка | Что ловит |
| --- | --- |
| Литеральные ключи `t('…')` | `t('Ban')` без перевода в `ru` |
| Словарь | пустой перевод; потерянная или лишняя `{подстановка}`; перевод, совпадающий с ключом (кроме имён тем) |
| Строки, похожие на текст интерфейса | английская строка, которой нет в `ru` и которая начинается с заглавной буквы, `{` или цифры («1 day»): так находятся динамические ключи, например `label: 'Ban'`, передаваемые в `t(label)`, и шаблонные подписи вроде `` `${n} KB` `` |
| Список исключений | запись в `NOT_INTERFACE_TEXT`, которая больше ничему не соответствует, — устарела |
| Вызовы `plural()` | у фразы нет русских форм `one`, `few`, `many` |
| `aria-label`, `label`, `title`, `placeholder`, `alt` | английская строка или шаблон вместо `t()` |
| Текст в JSX | видимый английский текст между тегами без `t()` |

Запуск (из `app/frontend`):

```
npx vitest run src/i18n      # только проверки перевода
npm test                     # все тесты
```

Если тест упал, он пишет `файл:строка "текст"`. Дальше два пути:

- это текст интерфейса — добавьте перевод в `ru` и пропущенный `t()`;
- это не текст интерфейса (название клавиши, код причины от сервера, сообщение для разработчика) — добавьте шаблон в `NOT_INTERFACE_TEXT` в самом тесте с короткой причиной. Это осознанное решение, а не способ заглушить тест.

Тест не выполняет код и не видит текст, собранный из частей во время работы, поэтому проверка «на глаз» остаётся: переключите язык на русский и пройдите изменённый экран. Проверки отображения на русском есть в `components/localizationRu.test.tsx`; остальные тесты запускаются на английском (`src/testSetup.ts`), поэтому для проверки русского текста язык в тесте надо выставить явно:

```ts
setPrefs({ ...DEFAULT_PREFS, appearance: { ...DEFAULT_PREFS.appearance, language: 'ru' } });
```
