# FinchSpeak — план дальнейшей работы

- **Дата:** 2026-10-15. Состояние на момент составления: `main` = `aa5e60b`, дерево зелёное (201 Rust-тест, 51 frontend-тест, clippy и `npm run build` чистые). Базовые сценарии (вход, чат, голос, демонстрация экрана 1920×1080) проверены на одной машине через два клиента.
- Статус открытых находок — в [HANDOFF.md](HANDOFF.md) (раздел 0) и в конце [отчёта аудита](audit/2026-10-audit-report.md).

## Правила работы

- Один баг или функция — один коммит; тест пишется первым; в коммите ID находки (`AUD-NNN`), если он есть.
- Перед коммитом: `cargo check --workspace --all-targets`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, в `app/frontend` — `npm test` и `npm run build`.
- После каждого этапа: запуск двух клиентов и прогон ключевых сценариев через окна (WebView2 с `--remote-debugging-port`, отдельная `WEBVIEW2_USER_DATA_FOLDER` на каждый клиент), затем обновление `HANDOFF.md` и ручного чек-листа.
- Нельзя ослаблять пороги качества без согласия владельца. Нельзя заявлять проверенным то, что требует слуха, железа или человека: такие пункты уходят в [чек-лист](audit/manual-voice-checklist.md).
- Push в `origin` — только по подтверждению владельца.
- Правила кода: без `unwrap()/expect()/todo!()` в сетевом, серверном и аудио-коде; `finch-server` не зависит от `finch-audio`/`finch-screen`/`finch-client-core`; в колбэках cpal нет мьютексов и аллокаций.

## Этап 1. Ошибки и недоделки (≈1–2 дня)

| # | Задача | Проверка |
|---|---|---|
| 1.1 | Показывать отображаемое имя (`display_name`), а не логин, в сообщениях и списке участников | Тест стора; проверка в окнах приложения |
| 1.2 | Демонстрация экрана: поднять 16 FPS до 30 на 1080p. Сначала замер по стадиям (захват, конвертация, кодирование, отправка), затем убрать лишние копии кадра и вынести кодирование в отдельный поток | Замер FPS в двух окнах до и после; значение записать в `BASELINE.md` |
| 1.3 | Повторная подписка зрителя после переподключения | Тест в testbed: обрыв, возврат, картинка снова идёт |
| 1.4 | Передавать задержку устройства вывода в AEC3 (`stream_delay_ms`) | Тест ERLE с заданной задержкой |
| 1.5 | Экран больше 3840×2160: масштабировать до допустимого размера вместо отказа | Юнит-тест масштаба; декодирование кадра |
| 1.6 | Адаптация битрейта демонстрации под потери (по частоте запросов ключевых кадров) | Testbed с потерей пакетов |

## Этап 2. Звук демонстрации экрана (≈2–3 дня)

- Клиент: захват системного звука (`finch-screen::audio_loopback`), Opus stereo, отправка с типом `ScreenAudio`.
- Приём: отдельный канал микшера, своя громкость, кнопка отключения звука.
- Остановка вместе с демонстрацией, при выходе из комнаты и при обрыве.
- Тест: тон на отправителе доходит до зрителя без искажений и не смешивается с голосом.
- Человек: слышно ли звук, нет ли эха (добавить в чек-лист).

## Этап 3. Доводка голоса, подпроект 2 (≈3–4 дня)

- Push-to-talk с настраиваемой клавишей.
- Регулировка громкости микрофона.
- Тест «слышу себя».
- Порог VAD в настройках.
- Белый шум −35 дБFS (3,3 % речевых кадров, предел из `BASELINE.md`): трогать только если мешает на живом микрофоне.

## Этап 4. Профиль и чат, подпроекты 3–4 (≈1–2 недели)

Для крупных пунктов (профиль, реакции) сначала короткая спецификация, чтобы не переделывать.

- Экран настроек: аватар, смена отображаемого имени и пароля (AUD-043).
- Загрузка файлов в интерфейсе, ссылки на вложения, превью картинок (AUD-041).
- Редактирование и удаление сообщений, ответы (AUD-044).
- Реакции (таблица `message_reactions` есть, API нет), упоминания, «печатает», счётчик непрочитанных.

## Этап 5. Доступ и эксплуатация, подпроекты 5–6 (≈1–2 недели)

- Регистрация по приглашениям вместо открытой (AUD-027).
- Роли, кик, бан с отзывом токенов, переименование и порядок каналов (AUD-045).
- Установщик Windows, автообновление, бэкапы БД, ротация логов (AUD-046).
- Проверка Docker-развёртывания после перехода REST на HTTPS.

## Известные ограничения до выполнения плана

- Захват экрана и воспроизведение видео проверены только на одной машине, звук, эхо и шум на живом микрофоне — не проверены (см. HANDOFF 0.4).
- Вторую копию клиента на одной машине можно запустить только с отдельной папкой данных WebView2 (на разных машинах проблемы нет).
- Звук демонстрации экрана не реализован (этап 2).
