FinchSpeak работает на вашем сервере: вы запускаете его на одном компьютере, а участники подключаются через клиент. Сервер передаёт голос и видео без перекодирования. Интерфейс доступен на русском и английском языках.

## Возможности

- Голосовые комнаты с push-to-talk, управлением микрофоном, громкостью участников и локальной проверкой звука.
- Улучшение голоса на базе WebRTC, RNNoise и Opus. Тест микрофона учитывает порог активации и не отправляет тестовый звук другим участникам.
- Текстовые каналы с ответами, реакциями, упоминаниями, поиском и вложениями.
- Демонстрация окна или экрана с передачей системного звука.
- Приглашения, роли, модерация, управление каналами и резервные копии сервера.
- Две полноценные темы: **Claude Dark** включена по умолчанию; **Finch Custom** создана по отдельному дизайн-проекту. Тема и язык переключаются без перезапуска и сохраняются на компьютере.

## Запуск на двух компьютерах

Скачайте файлы **из одного выпуска** на странице [GitHub Releases](https://github.com/qwers451/FinchSpeak/releases): `FinchSpeak-server-windows.zip` для серверного ПК и `FinchSpeak_1.2.0_x64-setup.exe` для каждого клиента. Архив `FinchSpeak-windows.zip` содержит и сервер, и переносимый клиент.

1. На серверном ПК нажмите «Извлечь всё» для серверного ZIP. Оставьте файлы вместе в папке, доступной для записи, и запустите `Run_Server.bat` **из распакованной папки**. Окно сервера должно оставаться открытым.
2. Разрешите в брандмауэре **TCP 8443** (вход и файлы) и **UDP 4433** (голос и видео). Для теста в одной локальной сети узнайте IP-адрес серверного ПК командой `ipconfig`. Доступ через интернет дополнительно требует проброса этих портов на роутере.
3. Установите клиент на обоих ПК. В поле адреса сервера введите `https://IP-СЕРВЕРА:8443`, например `https://192.168.1.50:8443`.
4. При первом подключении сравните показанный клиентом отпечаток сертификата с отпечатком в окне сервера и подтвердите совпадение.
5. Создайте первый аккаунт — он станет администратором. Готовых аккаунтов нет. Для второго участника в клиенте администратора откройте **Администрирование → Приглашения**, создайте код и передайте его второму пользователю для регистрации.
6. Войдите в одну голосовую комнату с обоих ПК. В настройках **Голос и звук** проверьте выбранные устройства, «Тест микрофона», порог активации и при необходимости push-to-talk. Для оценки звучания используйте наушники и разговор между двумя устройствами.

Подробные сценарии приёмки: [чеклист для двух ПК](docs/RELEASE-CHECKLIST.md). Если клиент не подключается, сначала проверьте, что серверное окно открыто, оба ПК видят друг друга по сети и адрес содержит `https://` и порт `8443`.

## Темы и язык

В **Профиль и настройки → Внешний вид** можно выбрать оформление и язык:

| Тема | Характер |
| --- | --- |
| Claude Dark | Тёплая тёмная палитра, спокойная типографика и мягкие переходы. Используется по умолчанию. |
| Finch Custom | Контрастный технический стиль с формами, иконками и иллюстрациями из дизайн-проекта. |

Обе темы используют одну актуальную птицу FinchSpeak. Она также присутствует в значке приложения, установщика и трея. Анимация учитывает настройку уменьшения движения в системе.

## Данные, обновления и доверие

Сервер хранит базу данных, вложения, журналы, резервные копии и сертификат рядом с исполняемым файлом. Перед переносом или обновлением сервера сохраните **всю его папку**; особенно важны `finchspeak.db`, `data/` и `finch-server.toml`. Для обновления остановите сервер, сделайте копию папки, замените `finch-server.exe` и запустите `Run_Server.bat` снова. Клиент проверяет подписанные обновления через GitHub Releases.

Соединение клиента с сервером защищено TLS 1.3; при первом подключении клиент просит подтвердить отпечаток сертификата. Сквозного шифрования между участниками нет: администратор своего сервера управляет его инфраструктурой. Windows может показать предупреждение SmartScreen, поскольку установщик не имеет подписи Authenticode. Сверяйте источник загрузки и `SHA256SUMS.txt` из того же выпуска.

## Сборка и проверки

Нужны актуальный стабильный Rust, Node.js и Windows C++ Build Tools. Нативный аудиомодуль требует отдельной подготовки; порядок и проверка зависимостей описаны в [NATIVE-AUDIO.md](docs/NATIVE-AUDIO.md). Для фронтенда:

```powershell
cd app/frontend
npm ci
npm test
npm run build
```

После подготовки нативного аудио из корня репозитория:

```powershell
cargo test --workspace -- --test-threads=1
cargo clippy --workspace --all-targets -- -D warnings
```

Клиент — Tauri 2 и SolidJS; сервер и медиатракт написаны на Rust. Исходный код компонентов находится в [`app`](app) и [`crates`](crates). Результаты автоматической проверки выпуска 1.2.0 и границы ручной проверки приведены в [QA-1.2.0.md](docs/QA-1.2.0.md).
